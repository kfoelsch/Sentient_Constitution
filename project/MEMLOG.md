## Standing Decisions

**Constitutional Constraints bind globally (steward decision, 2026-10-14):** every system, institution, and other body is bound at every class and in every context, including Class P and sandboxed scope. Class scales the intensity, form, and machinery that carry a constraint, never whether it applies.

**Burden of proof falls to the claimant (steward decision, 2026-10-14):** a body claiming to be below a line shows it with a short written statement; a challenger names a specific crossing in a named domain, and the body then shows it is below that line (Chapter Four §1).

**Time windows (custodian decisions, 2026-10-17 and 2026-10-18):** restricted evidence never slows the clock and is never a ground for a slower column or a longer window; a "reasonable" period is 14 days; "promptly" is not a length, and review of a measure in force, intake, and notice name their windows instead; record duties follow Document at Action (Chapter One §16.4), a design default and not a window; window names live in CJS-0.4 and the numbers stay with their owners (Chapter Thirteen §6, CF-11.3.1); no Chapter Five definitions for window names or for the new principle unless a core rule needs to cite them.

**The word "instrument" is not used (custodian decision, 2026-10-19):** name the thing (System Charter, Institutional Charter, rule set, record, act), or write "document" or "text"; for the Constitution itself, "this Constitution". The audit rule `avoid-instrument` enforces it on live files; dated records and translations keep their wording.

**Chapter Nine order (editor decision, 2026-10-07):** Chapter Nine sections follow the order the certification work is done. New sections go in the phase where the work happens, not at the end of a file. Renumbered before the announcement so no redirect anchors are needed later.

**Go-live gate (editor decision, 2026-10-08):** No system goes live, pilot or full, before it is certified. A pilot is certified on its own record, scaled by class and substitutability. Systems already operating at an adopter's effective date are excepted only for the Article XXVIII-A transition clock. The published record challenge path opens when the outcome is published, or is already open for a system already operating.

**Translation scheduling (steward planning decision, 2026-10-20):** Prepare translations chapter by chapter once the steward identifies settled English text and its revision, followed by a final synchronization and fidelity review. Do not treat any chapter as settled without that identification. The [announcement plan](plans/announcement_readiness_2026-10-20.md) tracks readiness. Historical pause details and known gaps are in [MEMLOG_SNAPSHOT_2026-10-20.md](../archive/MEMLOG_SNAPSHOT_2026-10-20.md); PR #109's updates did not certify translations.

## Operating Rule

Add new session entries above the archive index only when they carry forward current context, decisions, verification status, or next actions. For detailed closure narratives, create a dated archive snapshot and leave a pointer here.

Standard closeout order: commit substantive corpus/source changes first; then snapshot active meta files (`TODO.md`, `MEMLOG.md`, and living worklists) into `archive/`; then slim the active meta files to pointers and current open work.

**Archive (standard procedure, custodian decision, 2026-11-08; step 2 and the same-day rule changed 2026-11-14, custodian, asked in session):** when the custodian says "archive", move every completed entry out of `project/MEMLOG.md`, `TODO.md`, and `doc_architecture.md`, as follows. (1) Work on the shared `work` branch in the session's own clone, started from `origin/work`, and push it (GIT-LOCAL-SYNC-01); the custodian's checkout gets the result through `make sync-local`, not by copying files into it. The text moved out in (3) to (5) is the archive, and the pre-cleanup state stays in git history, so name the base commit in the pointer. A file with nothing to move gets no archive file. (3) `TODO.md`: move sections and checked items with no open work to `archive/TODO_RESOLVED_<date>.md`. (4) `project/MEMLOG.md`: move completed session detail to `archive/MEMLOG_RESOLVED_<date>.md`; standing decisions and open threads stay. (5) `doc_architecture.md`: move the dated move-log entries that are complete and merged to `archive/DOC_ARCHITECTURE_MOVES_<first>-<last>_ARCHIVED_<date>.md`, leave a pointer, and keep the `**Next file:**` footer at the end. (6) Before moving anything, read each candidate for "not done", "open", or "pending" language and carry any genuinely open item into `TODO.md`. (7) Add pointers in the Archives lists and log the run as the next move in `doc_architecture.md` (numbered from the shared log on `origin/work`, MOVE-NUMBER-01). (8) Run `make preflight` and `make audit-report`, and check `git status` for evidence-file deletions that `audit-report` makes. One set of files per date: when an archive file for the same date exists from an earlier run, append the newly moved text to it, and extend the move-log file and rename it to the new move range with its pointers updated, instead of starting a second file with a `b` suffix. Nothing is deleted without being archived first, and no rule or decision changes.

**Merge (standard procedure, custodian decision, 2026-11-09; route changed 2026-11-19 to the shared `work` branch):** when the custodian says "merge", that is the request to merge everything on `work` into `main` in one run; it is the ask that [AGENTS.md](../AGENTS.md) and GIT-PUSH-CL-01 require before a session merges. (1) Make sure every move is committed and pushed to `origin/work` (GIT-LOCAL-SYNC-01, *one central folder*); work that began on the custodian's computer comes across by the route in AGENTS.md. Untracked scratch (`.vscode/`, `_sync/`, dated `evidence/` folders, translation drafts) stays out. (2) Check that every move on `work` has its move-log entry with a final number (MOVE-NUMBER-01), and run `make preflight` and `make corpus-markdown-audit` on `origin/work`; run `make audit-report` for larger changes. Watch `git status` for evidence deletions that `audit-report` makes, and do not restore them with `git checkout -- evidence`. (3) End any commit message with the attribution lines the session was given. (4) Open the pull request from `work` to `main` with `gh api` (GraphQL is blocked) and a body that lists the moves on it. (5) Wait for the `regression` check and compare any failing target with `main`; merge with a merge commit (`merge_method=merge`) only when the pull request adds no failing target that `main` lacks. If the check fails, stop and report; never force-push. (6) Run `make sync-local` on the custodian's computer, with a fresh `_sync/origin.bundle` when it cannot fetch; the checkout stays on `work`, which now matches `main`. Never sync by copying files. If the computer cannot be reached, say so and sync as soon as it is back. Delete the run's bundles and patch files in the project files. (7) Report the pull request number and link, the merge commit, and the moves it carried.
