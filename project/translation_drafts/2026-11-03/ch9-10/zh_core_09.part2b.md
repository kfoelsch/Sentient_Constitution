#### 3.1 治理、激励与可质疑性纪律

*用直白的话说：审查者必须询问，[四元](core_00.000_preamble.md#constitutional-tetrad)的四个支柱能否在相关风险等级下继续支撑——参与（感知者能否真正参与）、监督（工作能否被观察和核验）、问责（不当行为能否被追究），以及及时性（重要时刻能否及时作出决定）。审查者还必须查明谁实际掌握实质权限、谁对什么负责，而不是含糊地说「团队」或用空壳推卸责任。有效认证必须回答这些问题。*

如果认证评估没有判断下列每一项能否按比例适应待审系统的[实质利害](core_00.000_preamble.md#material-stake)，评估便不完整：

- **监督**；
- **问责**；
- **参与**；以及
- **及时性**。

评估还必须核验，下列各类实质角色均已得到**正式分配、记录并可追溯**，其程度足以让感知者知道应向谁问责，并能实际质疑决定：

- 尽责管理角色；
- 治理角色；以及
- 问责角色。

这须依照系统类别和实质影响作相应调整，依据为 **[CS-9.305](corpus_systems/cs_09.305_system_classification_machinery.md#cs-9305-part-a-system-classification-machinery)（*系统分类机制*）及 [CS-9.310 — System impact classifications](corpus_systems/cs_09.310_system_impact_classifications.md#cs-9310-part-b-system-impact-classifications)**。系统类别也决定复查时间表（[§2 System Class Evaluation](#2-system-class-evaluation)）。

为评估治理、激励和可质疑性，认证必须适用以下规定：

- **[Chapter One §16 Stewardship In Depth](core_01.010_stewardship_capacity_principles.md#16-stewardship-in-depth)** — 分布式理解、透明度、可审计性和可质疑的可观察性；
- **[Chapter One §18 Governance Under Stewardship Discipline](core_01.010_stewardship_capacity_principles.md#18-governance-under-stewardship-discipline)** — 经授权的治理与责任承担；
- **[Chapter One §19 Incentive Alignment and System Capture](core_01.010_stewardship_capacity_principles.md#19-incentive-alignment-and-system-capture)** — 代理指标完整性、短期缺陷纠正和应对俘获，包括：
  - **[Chapter One §19.1.4 Role-Depth and Material-Responsibility Pathways](core_01.010_stewardship_capacity_principles.md#1914-role-depth-and-material-responsibility-pathways)** — 会造成真实后果的角色，以及防止象征性参与的保障措施；
- **[Chapter Fifteen §5 Authorized Roles, Competency Development, and Contribution](core_15.000_governance.md#5-authorized-roles-competency-development-and-contribution)**及**[CS-15.305 — Critical system stewardship](corpus_systems/cs_15.305_critical_system_stewardship.md#cs-15305-critical-system-stewardship)** — 在具有实质影响时，适用的角色定义、能力和可追溯性要求；
- 当审计、透明度或独立核验方面的权利底线存在实质利害时，适用**[Article XVI: Audit, Transparency, and Independent Verification](core_06.010_rights_part_c.md#article-xvi-audit-transparency-and-independent-verification)**。

**机构事实。** 本节询问系统运营方或尽责管理方的治理和激励情况。如果运营方或尽责管理方是[机构](core_05.040_band_continuity.md#institution)，这些事实只在其机构认证记录中查明一次，而不必为其运营的每个系统重复查明。下列机构事实可以链接引用其当前记录，依据为[Chapter Ten §3 Whole-Institution Certification Evaluation](core_10.000_institutional_alignment_certification.md#3-whole-institution-certification-evaluation)：

- 机构自身的治理；
- 机构中承担责任的职务；以及
- 机构的奖励结构。

第十章不会仅凭机构自己的说法采纳这些事实，而会以证据和观察到的运行情况检验，并在每项认定中说明依据。若没有当前有效的机构认证记录，则依照本节直接评估这些事实。

就这些事实而言，本系统的评议所：

- 仍须决定这些事实是否足以适用于本系统；并且
- 若不在System Certification Record中说明理由，不得对同一机构事实作出不同认定。

本节仍会评估系统自身的治理、激励和可质疑性。见[Chapter Ten §1 Purpose and Role](core_10.000_institutional_alignment_certification.md#1-purpose-and-role)。

**作为 Type O 发布。** 本节确立的是认证数据；依照[CS-6.310 Part B §9.3 Type O](corpus_systems/cs_06.310_data_classifications.md#93-type-o-open-public-oversight-baseline-disclosure-data)，所有系统类别的认证数据都是 **Type O**。它不是私人认定。所涵盖的内容包括：

- 监督、问责、参与和及时性评估；
- 分配的尽责管理、治理和问责角色，以及谁掌握实质权限、谁对什么负责；以及
- 作为依据的机构事实，包括其治理、承担责任的职务及奖励结构。

这些内容须通过[System Certification Record](core_05.040_band_continuity.md#system-certification-record)按公共基线的保真度发布，并遵守**[CS-6.305 §7 Type O baseline](corpus_systems/cs_06.305_information_types_and_handling.md#cs-6305-7-type-o-baseline-for-class-abc-systems)**规定的替代和暂缓披露规则。对于**Class A**、**Class B**和**Class C**系统，这也属于[Public Oversight Baseline Disclosure](core_05.050_band_oversight.md#public-oversight-baseline-disclosure)的一部分；[§3.4.1 Type O Baseline Disclosure](#341-type-o-baseline-disclosure)会核验其是否确已发布。

对于**Class L**和**Class P**系统，完整的Public Oversight Baseline Disclosure不适用，但这些认证数据仍属于**Type O**。披露的细节程度依照[CS-9.310 §8.6 Scaled-duties intensity](corpus_systems/cs_09.310_system_impact_classifications.md#86-scaled-duties-intensity)中该系统类别的透明度义务确定。Class L或Class P系统若重新分类为Class C或更高类别，则从重新分类时起适用完整基线。

<a id="32-systemic-scope-and-risk-factors"></a>
#### 3.2 系统性范围与风险因素

认证评估必须考虑：

- **最大规模的伤害：**
  - **生态恢复能力** — 系统是否可能以任何规模损害任何自然生态系统的[生态恢复能力](core_05.040_band_continuity.md#ecological-recovery-capacity)，使其受损后无法再生；
  - **生存性风险** — 可能威胁文明尺度感知者生存的结果；
- **影响如何扩散和累积：**
  - **依赖关系与连锁影响** — 上游故障时，下游哪些部分会失效；
  - **聚合与规模效应** — 许多小行动合并时会发生什么变化；
  - **延迟、累积和概率性影响** — 日后显现、不断叠加或取决于偶然性的伤害；
- **系统可能如何遭到滥用或范围错置：**
  - **对抗条件与滥用可能性** — 不良行为者或可预见的滥用如何利用系统；
  - **章程范围与功能边界** — 如存在或要求[System Charter](core_05.040_band_continuity.md#system-charter)，其是否符合观察到的[System Boundaries](core_05.040_band_continuity.md#system-boundaries)，以及所述范围是否低估了实质影响或依赖。

<a id="321-risk-evaluation-and-disclosure-bridge"></a>
##### 3.2.1 风险评估与披露衔接

若上述因素使系统性[风险](core_05.040_band_continuity.md#risk)成为评估范围的一部分，认证必须核验第五章中两项配套要求都已满足，而不是另行创造一种具名的风险披露记录：

- **[Risk Evaluation](core_05.040_band_continuity.md#risk-evaluation)** — 是否确实评估了系统性风险：
  - 是否在重要条件下评估（依赖关系、时间范围以及[对抗、规模化和受利用条件](core_05.050_band_oversight.md#adversarial-scaled-and-exploited-conditions)）；并且
  - 评估层级是否符合系统类别和[实质利害](core_00.000_preamble.md#material-stake)。
- **[Risk Disclosure](core_05.050_band_oversight.md#risk-disclosure)** — 已评估的风险是否：
  - 传达给需要了解的感知者；并且
  - 及时传达，使他们有时间理解、质疑并采取行动。

<a id="322-defects-and-misalignment"></a>
##### 3.2.2 缺陷与不一致

上述两项要求只做到其中一项，均不合格：

- 评估了风险却从未共享，不能通过；并且
- 共享了风险却未妥善评估，也不能通过。

内部便笺、埋在附录中的说明、核对清单或事后声明，既不算风险评估，也不算风险披露。

下列任一情况都必须视为认证缺陷：

- 在[Transparency](core_05.050_band_oversight.md#transparency)或[Safety (Constitutional Constraint)](core_05.040_band_continuity.md#safety-constitutional-constraint)要求披露时，未向需要了解者披露已评估的系统性风险；或
- 已知风险仍未记录、披露和处理，却签署同意继续依赖该系统。

这些缺陷的后果见[§7 Certification Outcomes](core_09.005_system_alignment_certification_record_process.md#7-certification-outcomes)。
