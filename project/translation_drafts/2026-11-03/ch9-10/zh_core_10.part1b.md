#### 1.2 设立或运营无需许可且不设门槛

机构对齐认证是对机构如何实际行使权限所作的独立检查。该检查由独立于机构的评议所进行，最终形成一份记录其认定的Institutional Certification Record。

- **设立与运营：**机构可以成立、发布其Institutional Charter、开始行使权限并持续运营，无须先取得认证；任何结果都不会授予或剥夺这一权利。
- **结果的影响：**结果仅产生[§7.1 机构的上线](#71-go-live-for-an-institution)所述影响。
- **本领域仅有的门槛：**共有三项狭义门槛，均见**Article XI-E**（*机构成立与企业创建*）：
  - 对具名感知者尚未解除的限制，该限制附着于该感知者的权限；
  - 对特定且经核验的不对齐事实作出的Interim Hold，该限制同样附着于具名感知者的权限；
  - 对Operating Party本身的限制，只有在该限制针对该机构时才附着于机构，例如**CI-12.210 §4**（*解散*）对已解散机构施加的限制。

  认证认定可作为证据，转交给负责裁定上述门槛之一的评议所，依据为[§7.5 拒绝和撤销对机构的影响](#75-effects-of-denial-and-revocation-for-an-institution)。认证结果本身不是门槛，也不会开启或关闭门槛。
- **等待取得新的实质权限：**机构决定取得新的实质权限时，必须依照[§9.2.2 新的实质权限的再认证](#922-recertification-for-new-material-authority)，等该权限通过再认证后才能行使。**Article XI-E**（*机构成立与企业创建*）规定了这项等待要求。它不属于三项狭义门槛，也不限制机构的成立或运营。它只针对新的权限，机构的其他活动均继续进行。[§9.2.2 新的实质权限的再认证](#922-recertification-for-new-material-authority)中的图示总结了各步骤。
- **不得设置后门：**评议所、采纳者或现任权力者都不得将本章用作授权门槛，借此排斥创始者或保护现任者。这样做会违背[Article XI-E](core_06.005_rights_part_b.md#article-xi-e-institutional-formation-and-business-creation)（*机构成立与企业创建*）。
  - [Avoidable Burden](core_05.040_band_continuity.md#avoidable-burden)适用于流程成本。
  - [Classification-Scaled Governance](core_05.050_band_oversight.md#classification-scaled-governance)适用于审查深度。
  - 新的实质权限等待要求对每个同类别机构均按相同条件适用，并且只针对已对他人产生实质影响的权限。

System的上线门槛彼此独立，仍由System自身承担。依照[Chapter Nine Part B §7.1 Go-Live Gate](core_09.005_system_alignment_certification_record_process.md#71-go-live-gate)，新System或System的实质扩展，只有经过其自身认证才能上线，无论机构处于何种状态。

<a id="13-window-for-the-first-certification"></a>

#### 1.3 首次认证的期限

机构必须在采纳文件为其类别规定的期限内提交首份Institutional Certification Record。

- **新机构：**期限从机构首次对他人产生实质影响之日起计算，依照[Domain-Specific Materiality](core_05.050_band_oversight.md#domain-specific-materiality)判定；其首次认证为临时认证。
- **通知后重新分类的Class P机构：**期限从机构依据[§9.2.2 新的实质权限的再认证](#922-recertification-for-new-material-authority)发出通知之日起计算，与新机构相同，绝不从已经结束的Adoption Transition期限起算。
- **已经运营的机构：**期限为依据[Article XXVIII-A](core_06.020_rights_part_e.md#xxviii-a-existing-instantiations-adoption-transition-window)（*分阶段采纳与权利底线连续性*）设定的Adoption Transition期限，并符合[Chapter Seven §1.5 When a System Charter or Institutional Charter is due](core_07.000_charters.md#15-when-a-system-charter-or-institutional-charter-is-due)中的默认规则。
- **错过期限：**机构未在期限届满前完成首次认证流程，且不符合下述豁免条件时，须记录并纠正该缺陷；错过期限本身会启动该认证流程。已运营的Class L或更高类别机构还会出现下述里程碑违约。由于没有门槛，机构不会因此被停止或禁止运营（[§1.2 设立或运营无需许可且不设门槛](#12-no-permission-and-no-gate-on-forming-or-running)）。
  - **已运营的机构：**这是本章针对Class L或更高类别机构自行设定的规则，类比[Article XXVIII-A](core_06.020_rights_part_e.md#xxviii-a-existing-instantiations-adoption-transition-window)（*分阶段采纳与权利底线连续性*）对Systems和衍生实体的规定。如果Adoption Transition期限届满而首次认证流程尚未完成（既没有临时或完整认证，也没有依据[§7 Certification Outcomes](#7-certification-outcomes)作出已裁定结果），即视为错过期限。若机构在期限内提交申请并配合，但认证流程因评议所超时而未完成（[Chapter Fourteen §6 Timely resolution, materiality tiers, and anti-delay discipline](core_14.000_forum.md#6-timely-resolution-materiality-tiers-and-anti-delay-discipline)，*超时审查*；[Chapter Nine Part C §9.3.4 Tier windows](core_09.010_system_alignment_certification_record_recertification.md#934-tier-windows)），或因[§7.3 Remediation readiness for an Institution](#73-remediation-readiness-for-an-institution)规定的单次延期仍在进行，则不视为错过期限。除非机构依据[Article XXVIII-B](core_06.020_rights_part_e.md#article-xxviii-b-adoption-transition-authority-limits-and-reauthorization)（*分阶段采纳权限限制与重新授权*）持有有记录的重新授权，否则此事构成Adoption Transition里程碑违约，并启动[Chapter Eleven](core_11.000_standing_assessment.md#chapter-eleven-contribution-violation-and-standing-model--measurement)中的常规合规与违规路径。该Article中的限制义务自生效日起适用，不能因缺口持续存在就让其成为新常态。这与[Chapter Nine Part B §7.1.1 Systems already operating](core_09.005_system_alignment_certification_record_process.md#711-systems-already-operating)一致。这不是门槛。
  - **认证流程：**与其他认证流程一样裁定。结果可以是[§7 Certification Outcomes](#7-certification-outcomes)中的任何一种，包括Not Certified，并产生[§7.5 拒绝和撤销对机构的影响](#75-effects-of-denial-and-revocation-for-an-institution)所述影响。
  - **制裁与解散：**本章不设任何制裁。暂停、接管、结构性分离和解散仍由依照**CI-12.210**（*机构失败与解散*）及**CI-12.215**（*机构问责与制裁*）具有管辖权的评议所处理。只有符合[§7.5 拒绝和撤销对机构的影响](#75-effects-of-denial-and-revocation-for-an-institution)（第5项，*移交*）所列移交理由时，才转交该评议所。

<a id="21-institution-class"></a>

#### 2.1 机构类别

**机构类别**依据机构造成的最大实质影响确定，无论影响是通过其运行的System产生，还是在任何System之外产生。判断依据是机构实际决定、持有和控制什么，而不是其标签、法律形式或Institutional Charter中的清单。类别决定评估深度和时限，作用方式与[Chapter Nine Part A §2.2 How system class scales every evaluation](core_09.000_system_alignment_certification_evaluation.md#22-how-system-class-scales-every-evaluation)对System的规定相同。本章和[Chapter Seven §1.2 Which classes are covered](core_07.000_charters.md#12-which-classes-are-covered)均使用该类别。

1. **通过Systems产生的影响：**机构类别至少等于其组合中最高System类别（[Chapter Seven §1 When System and Institutional Charters Are Required](core_07.000_charters.md#1-when-system-and-institutional-charters-are-required)）。依据观察到的运行情况识别Systems。未列入Institutional Charter的System仍须计入。
2. **在任何System之外产生的影响：**无论机构是否运行System，其自身的实质影响和依赖关系均须计入。**CS-9.305（*系统分类机制*）和CS-9.310**（*系统影响分类*）中的类别定义，适用于机构自身的决定和持有事项，并考虑以下因素：
   - **机构决定与持有什么：**
     - 机构如何决定其他感知者获取生存必需品、教育、安全、生计、权利或轨迹的渠道；以及
     - 机构持有什么，例如资金、记录、成员资格、轨迹记录保管职责，或评议所、认证者或记录办公室的职能。
   - **影响是否具有实质意义：**
     - 机构自身活动是否在[Domain-Specific Materiality](core_05.050_band_oversight.md#domain-specific-materiality)的任何领域具有实质意义，包括作出他人必须遵守或可以视为已确定事项加以依赖的[Materially Binding Acts](core_05.035_band_accountability.md#materially-binding-act)；
     - 依据**CS-9.305（*系统分类机制*）和CS-9.310**（*系统影响分类*），在任何一个领域具有实质影响的机构至少属于Class L；以及
     - 提供他人可以自由接受或拒绝，且不会控制任何人获取所需事物渠道的援助、商品、劳动力或服务，不会约束任何人。这属于行为，而非Materially Binding Act，并且只有通过其他因素才计入类别评估。
   - **有多少主体依赖该机构：**
     - 依赖机构的感知者人数，以及机构的可替代程度；
     - 机构权限的集中程度，依照Material Control Line的含义判断；以及
     - 机构决定的可逆性。
3. **共同控制：**依照[Domain-Specific Materiality](core_05.050_band_oversight.md#domain-specific-materiality)的合并规则（在[Material Control Line](core_05.035_band_accountability.md#material-control-line)内形成共同的实际控制；单凭资金关系不算），若若干Operating Parties在实践中作为一个机构行事，则合并分类。如果拆分Operating Party、其组合或权限，使得任何部分都达不到Class L，则依据[Chapter Three §2.1 Common Evasion Patterns](core_03.000_definition_integrity.md#21-common-evasion-patterns)构成范围和边界规避。
4. **重新分类：**依照[§9.2 Reopening triggers](#92-reopening-triggers)中的触发条件重新评估类别。Institutional Certification Record须记录分类及其理由。

<a id="22-scaling-by-class"></a>

#### 2.2 按类别分级

机构类别决定证据深度、审查独立性、默认认证期限及记录披露内容，其方式与[Chapter Nine Part A §2.2 How system class scales every evaluation](core_09.000_system_alignment_certification_evaluation.md#22-how-system-class-scales-every-evaluation)相同。认证期限见[Chapter Fourteen §6 Timely resolution, materiality tiers, and anti-delay discipline](core_14.000_forum.md#review-cadence)（*复查周期*）；采纳文件可以规定更短的期限，并决定所需的临时认证无缺陷再认证次数。

- **Class A、B和C：**[§3 Whole-Institution Certification Evaluation](#3-whole-institution-certification-evaluation)中的八项内容全部适用，证据和独立性要求按类别调整。
- **Class L：**同样适用八项内容，但流程可简化，记录可更简要；在[Classification-Scaled Governance](core_05.050_band_oversight.md#classification-scaled-governance)允许时，默认认证期限可更长。Class L认证流程的核心是将Institutional Charter与实际情况对照，检查Role Map、成立核验声明以及所引用System认证的有效性。不得省略任何项目；若某项目无可发现事项，也须用一句话说明。
- **Class P：**自愿采用，依照[§1.1 Who is certified](#11-who-is-certified)执行。

**联合专业执业中的托管机构。** 若机构是托管方（[**CI-15.205 §7**](corpus_institutions/ci_15.205_appointment_competency_rotation_removal.md#ci-46-seat-advisory)（*执业许可证、执业核准与联合专业执业*）），认证还须抽查成员的行为是否符合托管方承担的席位，并将成员的采纳通知与托管方实际行动对照。关于某一成员行为的认定，属于对该成员的认定；只有托管方承担的席位出现失职时，才会涉及托管方。

<a id="3-whole-institution-certification-evaluation"></a>
