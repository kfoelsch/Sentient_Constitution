#### 拒绝认证

*简言之，**拒绝认证**是指系统尚无认证状态，而运营方未能证明自己既有意愿也有能力纠正问题，因此不予认证。这是真实结果，不是威胁。它会改变系统的认证状态，但本身不会关闭系统。*

- **含义**
  - **范围内：**在首次认证、新审查或其他认证轮次中，对尚无认证状态的系统作出不予认证的结果，因为补救准备度检查未能证明运营方既愿意又能够纠正不一致或认证缺陷。
  - **范围外：**
    - [撤销认证](core_05.040_band_continuity.md#certification-revocation)，收回已持有的认证；
    - 延期认证，在有限期间推迟决定，并不拒绝任何事项；
    - 停止运营的命令，依据[第九章C部分§9.3.5](core_09.010_system_alignment_certification_record_recertification.md#935-class-a-reliance)的生存必需保护另行决定；以及
    - 状态影响或违规认定——只有[第十一章](core_11.000_standing_assessment.md#chapter-eleven-compliance-violation-and-standing-model)决定状态。
    这些事项各有归属条目。
  - **依赖项：**[系统对齐认证](core_05.040_band_continuity.md#system-alignment-certification)。
  - 条件和程序见[第九章B部分§7.4](core_09.005_system_alignment_certification_record_process.md#74-denial-and-revocation)，影响见[§7.5 拒绝的影响](core_09.005_system_alignment_certification_record_process.md#75-effects-of-denial-and-revocation)。本条目仅说明第五章中的含义。
<a id="certification-denial-a"></a>
- **测量与评估**
  - **主要测量：**[连续性测量组](core_05.010_apex_continuity_aim.md#measuring-continuity-preamble-measurement-family)——*感知者和系统能否在生态上、可靠地并跨越故障持续存在？*

    **主要评估：**
    1. 拒绝是否基于记录中的认定，即运营方未证明具有纠正意愿和能力，而非基于其规模、年龄、财富或竞争利益；
    2. 拒绝生效前是否写明临时保护和依赖限制，并通知依赖该系统的感知者；以及
    3. 决定拒绝前，运营方是否收到认定通知并有机会答复或提供证据步骤。
<a id="certification-denial-c"></a>
- **必须满足**
  - **主要失败：**
    - 没有记录补救准备度认定就拒绝认证，或基于与纠正无关的理由拒绝；
    - 准备度认定要求拒绝时却授予有条件认证；
    - 在替代方案尚未出现前，将拒绝视为切断生存必需服务的命令；或
    - 拒绝认证却不通知依赖系统的人。
