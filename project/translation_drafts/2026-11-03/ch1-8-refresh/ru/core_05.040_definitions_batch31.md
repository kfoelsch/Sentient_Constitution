#### Триггер возобновления

<details>
<summary><strong>Прослеживаемость</strong></summary>

- Канонический источник: глава девятая C §9.2 Основания возобновления; для учреждения также глава десятая §9.2. Читать с возобновлённым рассмотрением и записью системы.

</details>

*Проще говоря, это существенное изменение или сообщение, оправдывающее возобновление сертификации до плановой даты. Триггеры указываются в записи.*

- **What it is**
  - **In scope / out of scope / dependencies:** Входит существенное изменение/сообщение из перечня: изменение системы/контекста; наблюдение или сообщение; несоответствие классификации/типа данных; вопрос устава системы/управления оператором; несоответствие оценки. Возобновление вызывает только существенный триггер; нарушение управления — один из них. Не входит плановая дата повторной сертификации, не являющаяся триггером. Зависит от возобновлённого рассмотрения и записи системы. Триггеры — глава девятая C §9.2, для учреждения — глава десятая §9.2. Здесь только смысл главы пятой.
<a id="reopening-trigger-a"></a>
- **How to measure and assess**
  - Оценить, указаны ли триггеры в записи и приводит ли существенный триггер к возобновлённому рассмотрению.
<a id="reopening-trigger-c"></a>
- **What must hold**
  - **Primary failure:** Основные нарушения: запись без триггеров; игнорирование существенного триггера из-за близкой даты повторной сертификации.
