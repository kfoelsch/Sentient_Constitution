#### Нарушение управления

<details>
<summary><strong>Прослеживаемость</strong></summary>

- Канонический источник: глава десятая §9.6 Возобновление рассмотрения систем учреждения; читать с главой девятой C §9.2 Основания для возобновления. Также читать с возобновлённым рассмотрением, цитируемой системой, выводом о причине и учреждением.

*Проще говоря, это термин главы десятой для сбоя управления учреждением, который возобновляет проверку его систем. Он называет основание возобновления, а не нарушение статуса. Возобновление вызывает только существенный сбой.*

- **What it is**
  - **In scope / out of scope / dependencies:** Входит сбой управления учреждением, возобновляющий проверку систем: установление сбоя собственного управления; отказ/отзыв сертификации учреждения по основанию управления; или вывод о причине, относящий её к учреждению. Только существенное нарушение открывает проверку, и каждое решение открывает каждую систему один раз. Не входят нарушения статуса по главам одиннадцатой/двенадцатой; актуальность цитируемой сертификации системы, определяемая её записью. Зависит от возобновлённого рассмотрения, цитируемой системы, вывода о причине и учреждения. Основания, фильтр существенности и уведомление — глава десятая §9.6. Здесь только смысл главы пятой.
<a id="governance-violation-a"></a>
- **How to measure and assess**
  - Оценить, перечисляет ли запись учреждения каждую уведомлённую систему и дату; не меняет ли возобновление результат, статус или условие сертификации и не останавливает учреждение/систему.
<a id="governance-violation-c"></a>
- **What must hold**
  - **Primary failure:** Основные нарушения: считать нарушение управления нарушением статуса или основанием остановить систему; не уведомить, переложив обязанность на форум, вынесший решение.
