- システムの特権、配置、または継続教育規則が、誤りによって他者に重大な危害をもたらしうる職務（例えば臨床職）に就ける者を決める場合、システム認証記録は、評価をどのように検査できるか、センティエントがどのように再訓練できるかを示さなければならない。職務の重要性が高いほど、必要な詳細も増える。
- システムの訓練枠、推薦、または資格ルーティングのロジックが参加者を大きく順位づけ、または排除する場合、システム認証記録はそのロジックの仕組みと、センティエントがそれに異議を申し立てる方法を示さなければならない。提供する教育の一般的な短い説明だけでは足りない。誰にも見えず、異議も申し立てられないロジックによる順位づけは、[第1章 §3.1 公正](core_01.000_values_principles.md#31-fairness)が禁じる説明不能な規則である。
  - [Part C §8.2](core_09.010_system_alignment_certification_record_recertification.md#82-transparency-and-auditability-of-the-system-certification-record)（9.010 §8.2）（*記録の完全性*）；
*平易に言えば：一部のシステムは、多くの他のシステムやセンティエントが依存する共有基盤 — インフラ、サービス、資源 — に依存している。システムがその基盤を大きく利用する場合、認証では、何を取り出しているか — 資源、物品、サービス、労働、情報、または資金 —、基盤を維持するために十分なものを戻しているか、そして誰もが追跡できるほど明確にシステム認証記録へ示されているかを確認しなければならない。運営者による「帳簿は合っている」という説明だけでは足りない。本節は配分方式や数値目標を定めず、それらは他の文書が定める。本節が適用される場合に、システムの依存関係、取り出すもの、返すもの、および他者にとって公正な取り決めかどうかが実際に評価されたかを確認する。適用例：[CS-9.320 §8 システムクラス別のシステム間支援の適用例](corpus_systems/cs_09.320_system_alignment_certification_illustrations.md#cs-9320-8-illustrative-cross-system-support-application-by-system-class)。*
- 共有流域や地域送電網の基幹部分など、センティエントの生存に必要な共有基盤を利用するシステムは、依存関係マップと還流の最も強い証拠をシステム認証記録に示さなければならない。これらは[第1章 §9 共有システム容量](core_01.000_values_principles.md#9-shared-system-capacity)が長期的な能力を守る共有システムであり、**第III-A条**（*生存*）が、ここで最も強い証拠を求める理由である。
  - [Part C §8.2](core_09.010_system_alignment_certification_record_recertification.md#82-transparency-and-auditability-of-the-system-certification-record)（9.010 §8.2）（*記録の完全性*）；
  - システム認証記録は、一般的なベストプラクティスの記述ではなく、負担と便益および代理指標について最も強い分析を含めなければならない；かつ
  - システム認証記録は、運用上の重要度に応じた差別的影響および実質的公正に関する認定を文書化しなければならない；かつ
  - [Part C §8.2](core_09.010_system_alignment_certification_record_recertification.md#82-transparency-and-auditability-of-the-system-certification-record)（9.010 §8.2）（*記録の完全性*）；
- 関連文書：教育のアクセシビリティが関係する場合は**第IV-A条**（*教育への平等なアクセス*） — 教育固有のアクセシビリティは同条が所管する；請求、徴収、または停止が生存に不可欠な要素へのアクセスを終わらせうる場合は**第III-A条**（*生存*） — [§5.5.3](#553-system-class-scaling-and-escalation)の無応答保護の基礎となる有意な通知要件；**第VI-C条**（*差別禁止*）（裁定と運用）および**第XII条**（*利害関係者によるシステム参加、代表、および適正手続*） — 認証がフォーラム、行政、利害関係者、または執行への参加をゲート化する場合；[§5.5](#55-accessibility-evaluation)（*横断的なアクセシビリティ評価要素への接続*）。
- システムの請求または障害経路が、センティエントを生存に不可欠な要素から切り離すおそれがある場合、システム認証記録はセンティエントが実際に参加できることを示す最も強い証拠を含めなければならない。一般的なアクセシビリティ声明だけでは足りない。センティエントを締め出す障壁には、[第1章 §7.1 制限の規律](core_01.000_values_principles.md#71-limitation-discipline)に基づく正当化が必要であり、請求や障害の通知は、[第1章 §5.2 平易な言葉によるアクセシビリティ](core_01.000_values_principles.md#52-plain-language-accessibility-participation-and-stewardship-duty)に基づき、センティエントが読み、行動できるように書かなければならない。
- システムの請求、徴収、または停止のプロセスが、支払いを止めた場合または応答を止めた場合に、センティエントを生存に不可欠な要素から切り離すおそれがあるなら、理由を問わず応答できないセンティエント（重度のうつ病などの認知または精神的健康状態を含む）をどう保護するかを、システム認証記録に示さなければならない。システムはセンティエントが沈黙している理由を知る必要はない。本規則は請求、徴収、停止に[第1章 §3.1.5 現在の能力と積極的支援](core_01.000_values_principles.md#315-present-capability-and-proactive-help)を適用する。沈黙は同意ではなく、サービスを手放す選択でもない。センティエントが行動に移せない通知は、不可欠な関係を終了する前に[**第III-A条**（*生存*）](core_06.000_rights_part_a.md#article-iii-a-survival)が求める有意な通知ではない。システム認証記録は次を示さなければならない：
- センティエントの沈黙または不払いを同意、拒否、またはサービスを手放す選択として扱い、システム認証記録が[§5.5.3 システムクラスの段階化とエスカレーション](#553-system-class-scaling-and-escalation)に基づき示すべき保護を欠いたまま、生存に不可欠な要素を停止すること。
  - [Part C §8.2](core_09.010_system_alignment_certification_record_recertification.md#82-transparency-and-auditability-of-the-system-certification-record)（9.010 §8.2）（*記録の完全性*）；
- システムの測定値、警告、または回復の主張が、家庭や運営者に生存に不可欠なもの（センティエントが生きるために必要なもの）について誤解を与えるおそれがある場合、システム認証記録には、単なる信頼性の主張ではなく強い証拠を示さなければならない。依存はシステムの実際の挙動によって獲得されるからである（[第1章 §6 信頼](core_01.000_values_principles.md#6-trust-and-trustworthiness-coordination-integrity)）。その証拠は次を示さなければならない：
- システムの稼働時間、マッチング、または緊急時の上書き（「緊急アクセス」）の主張が、センティエントが臨床ケアや緊急サービスを受けられるかどうかを左右する場合（[第1章 §4 安全](core_01.000_values_principles.md#4-safety-harm-constraint)が扱うリスク）、システム認証記録は、システムの重要度に応じた詳しさで以下を示さなければならない：
*フォーラム手続と結果へ進む：* [第9章 Part B — フォーラム手続と結果](core_09.005_system_alignment_certification_record_process.md#chapter-nine-part-b-system-alignment-certification--forum-process-and-outcomes)（[§6 フォーラム手続](core_09.005_system_alignment_certification_record_process.md#6-forum-process)および[§7 認証結果](core_09.005_system_alignment_certification_record_process.md#7-certification-outcomes)）。*続いて、システム認証記録、再認証、およびステータスへの橋渡しへ：* [第9章 Part C — 記録、再認証、およびステータス](core_09.010_system_alignment_certification_record_recertification.md#chapter-nine-part-c-system-alignment-certification--record-recertification-and-standing)（[§8 システム認証記録](core_09.010_system_alignment_certification_record_recertification.md#8-system-certification-record)から[§11 ステータスとの関係](core_09.010_system_alignment_certification_record_recertification.md#11-relationship-to-standing)まで）。*
