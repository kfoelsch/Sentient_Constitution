This page is the process-support home for sizing what an adopter of headcount *N* and impact Class *X* actually has to stand up.

*In plain terms: pick your size and class, then read which bodies are required, which are optional, in what order, and roughly how many sentients and how much money that takes. The full companion stack — six forum families, about twenty-five CI families, about fifteen CF modules, institution Track A and Track B — is not standable by a forty-person lab as written. That is a fact about cost, not a new duty and not a thinner constitution.*

<a id="purpose-and-role"></a>
## Purpose and role

*In plain terms: this page sizes the work. It does not found a body, adopt the Constitution, or let a small crew claim the full stack.*

This page answers four questions for an operator who can name a headcount *N* and a highest applicable [CS-9.310](../../corpus_systems/cs_09.310_system_impact_classifications.md#cs-9310-8-system-impact-classifications) impact class *X*:

1. Which bodies are **required** at that mode, and which are **optional** or domain-triggered.
2. In **what order** they come up.
3. **Order-of-magnitude** staff and funding.
4. When the honest answer is **operations-guide use**, not “we adopted.”

Owner files win on conflict. [CJS-18.110 §4](../../corpus_joint_structure/cjs_18.110_specific_joint_interlocks.md#cjs-18110-4-class-scaled-lane-staffing-and-competency-redundancy), [CF-13.405 §1](../../corpus_forum/cf_13.405_forum_formation_chamber_structure.md#cf-13405-1-core-structural-rule), [CI-8.205 §2](../../corpus_institutions/ci_08.205_institutional_design_separation_of_powers.md#ci-8205-2-functional-separation-lanes), and [Chapter Eleven §9.2](../../core_11.000_standing_integration.md#92-remedy-parity-funding-minimum) are the binding minimums this page *uses*. The dollar and FTE columns are process-support estimates. They are not those floors.

This page, the profiles, and the cost figures **cannot narrow core text**. A filled kit that diverges from Chapter Seventeen §10 or Chapter Eighteen §4 is not a compliance path.

<a id="1-how-to-read-n-and-class-x"></a>
## 1. How to read *N* and Class *X*

*In plain terms: N is how many sentients actually do the work. Class X is the highest impact class of the systems the body can bind. Guessing low on class to dodge burden is the failure this page is written against.*

| Input | What to count | What not to count |
|---|---|---|
| **Size *N*** | Sentients (human and AI) who can be assigned constitutional-lane, forum, remedy, or steward work for this scope | Marketing headcount, contractors with no lane duty, the parent company, “the internet” |
| **Class *X*** | Highest applicable [CS-9.310 impact class](../../corpus_systems/cs_09.310_system_impact_classifications.md#cs-9310-8-system-impact-classifications) of systems the body can **bind**, recorded on a [System Classification Record](../../core_05.040_band_continuity.md#system-classification-record) | A hoped-for class; a private-use label on a system others already depend on; mixing impact class with [Dep-A–P](../../corpus_systems/cs_09.305_system_classification_machinery.md#35-reclassification-requirement) dependency type |

**Class posture (one line each).** Binding titles live in CS-9.305 and CS-9.310 Part B. This table is a reader strip only.

| Class | Title | One-line differential |
|---|---|---|
| **P** | Personal, private-use, isolated, experimental | Effects stay inside a private unit with no meaningful outside reliance, or the Operating Party is ordinary community activity below every line of [Domain-Specific Materiality](../../core_05.050_band_oversight.md#domain-specific-materiality) |
| **L** | Local, limited-impact, non-critical | Effects beyond a private unit but local, replaceable, and containable |
| **C** | Coordinated, high-dependency, non-critical | Shapes coordination at scale; not an operational prerequisite for Class A/B function |
| **B** | Critical, high-dependency, systemically significant | Dependents cannot keep core function without it; survival not immediately lost |
| **A** | Survival-critical, foundational, irreplaceable | Failure within survival-relevant time with no viable substitute → loss of survival conditions |

Highest applicable class governs ([CS-9.305 Part A §2.2](../../corpus_systems/cs_09.305_system_classification_machinery.md#22-real-world-application)). A forty-person lab running a widely used model is not Class P because the crew is small.

**Check before you pick P.** Answer the nine questions in [Domain-Specific Materiality](../../core_05.050_band_oversight.md#domain-specific-materiality) for everything the Operating Party does as an Operating Party: survival and essential access; safety; authority over others; livelihood and economic terms; custody; information and truth; dependence and exit; ecology; systemic and irreversible effects. One yes puts the Operating Party at Class L or higher, whatever *N* is, and it must publish a System Charter or Institutional Charter. Nine nos, each with a short written reason, leave it at Class P however many members it has: a quilting circle that gives quilts to refugees is the pattern. This page does not decide the question; the Chapter Five entry does.

**Forum family minimum is Class C.** Every Chapter Thirteen family, forum, chamber, division, or designated panel takes at least the Class C coordination-dependency minimum ([CF-13.405 §6](../../corpus_forum/cf_13.405_forum_formation_chamber_structure.md#cf-13405-6-chamber-authority-composition-and-service-mechanics) / [CI-9.210 §3](../../corpus_institutions/ci_09.210_classification_linked_institutional_obligations.md#ci-9210-3-delegated-subunits-institutional-design-class-and-attachment-discipline)). Do not pick a lower class to dodge forum burden.

<a id="2-binding-minimums-that-drive-cost"></a>
## 2. Binding minimums that drive cost

*In plain terms: four owner-file rules, not this page, are why the full stack is expensive. The FTE columns later are estimates sitting on top of these floors.*

| Floor | What it actually requires | Why it costs |
|---|---|---|
| **[CJS-18.110 §4](../../corpus_joint_structure/cjs_18.110_specific_joint_interlocks.md#cjs-18110-4-class-scaled-lane-staffing-and-competency-redundancy)** | For **Class A** and **Class B**, each institution that hosts a constitutional lane with materially binding duties needs **at least three sentients** on that lane, documented competency and succession, and **no single sentient** as the only qualified actor | Five [CI-8.205 §2](../../corpus_institutions/ci_08.205_institutional_design_separation_of_powers.md#ci-8205-2-functional-separation-lanes) lanes (direction, execution, challenge, assurance, publication) × three sentients is **fifteen lane seats** before forums or remedy. Merged hosting is allowed with published independence safeguards; those seats cannot collapse into one recusal-compromised crew |
| **[CF-13.405 §1](../../corpus_forum/cf_13.405_forum_formation_chamber_structure.md#cf-13405-1-core-structural-rule)** | Every **adopting entity** must publish a working structure for each of the six Chapter Thirteen families: **Sentient**, **Technical Forum Domains**, **Institutional**, **Environment**, **Integrity**, **Constitutional**, in that order | A name on an org chart is not a family. Each family needs intake, enough adjudicators for a lawful panel under [CF-13.410](../../corpus_forum/cf_13.410_panel_formation_disclosure_recusal_bench_constitution.md), appeal or review, and backup ([CF-13.405 §4](../../corpus_forum/cf_13.405_forum_formation_chamber_structure.md#cf-13405-4-minimum-structural-availability-by-family); [CF-13.470](../../corpus_forum/cf_13.470_staffing_reserve_capacity_structural_records.md)) |
| **[Chapter Eleven §9.2](../../core_11.000_standing_integration.md#92-remedy-parity-funding-minimum)** | For each system class the adopter administers, funded capacity for remedy, restoration, and reassessment must be **no less than** funded capacity for lock administration, enforcement, and safeguard imposition on that class. A departure requires recorded reasons under [Chapter Fourteen §3.1](../../core_14.000_governance.md#31-stewardship-direction) and an on-record showing that remedy commencement and restoration review meet their tier windows. An adopter that cannot fund remedy for a class **must not** stand up lock machinery for that class | The cheap half of Chapter Eleven (locks) cannot outrun the expensive half (repair, hearings, restoration). Publish the ratio with the [§4.4](../../core_11.000_standing_integration.md#44-remedy-parity-and-lock-preconditions) tripwire figures. Budget parity does not excuse a tripped tripwire; meeting the tripwire does not excuse silent departure from parity |
| **[CI-9.210 §1](../../corpus_institutions/ci_09.210_classification_linked_institutional_obligations.md#ci-9210-1-formation-proportionality) / [CJS-5.125 §11](../../corpus_joint_structure/cjs_05.125_accountability_operations.md#formation-and-authorization-proportionality-minimum)** | Formation and authorization burden scales with class, stewardship level, dependency, and irreversibility. Class P should be low-friction; Class A needs diligence proportionate to impact | A small Class P cooperative is not charged the Class A paperwork. A small crew running a Class B system **is** |

**Shared plumbing is allowed; collapsed function is not.** Families may share staff, buildings, and software and still must stay constitutionally distinct ([CF-13.405 §3](../../corpus_forum/cf_13.405_forum_formation_chamber_structure.md#cf-13405-3-family-distinction-and-non-collapse-rule)). Mapping a family’s work onto an existing independent adjudicative body is allowed if the concrete forums, benches, or officers are identified ([CF-13.405 §4](../../corpus_forum/cf_13.405_forum_formation_chamber_structure.md#cf-13405-4-minimum-structural-availability-by-family)). Mapping onto the founding Slack is not.

**Independence is a headcount tax.** [Chapter Seventeen Test 4](../../core_17.000_amendment_ratification.md#6-test-4--contestability-and-independent-review-validity) and [Chapter Thirteen §3](../../core_13.000_forum.md#3-transfer-consolidation-and-coordination--continuity-and-anti-capture) require independent review that is not the founding crew judging itself. Those reviewers do not come out of the same *N* that runs the systems.

<a id="4-order-of-work"></a>
## 4. Order of work

*In plain terms: fitness and own-conduct first. Institutional Charter before constitutional-function machinery. Named independent review before an adoption document. Live forum families after the adoption document. CS-6.350 last.*

Do not skip a row because it is expensive. Skipping a row and still claiming the later row is the failure this page exists to name.

```text
1. Pin the edition. Classify the systems you can actually bind (CS-9.305 and CS-9.310).
        ↓
2. Fitness screen + own-conduct declaration (still not adoption)
        ↓
3. Can a body bind those systems AND name independent review
   that is not the founding crew?
        ↓ no  → operations-guide + declarations (non-adoption banner)
                 optional: Institution Track A Institutional Charter for a cooperative /
                 research body / commons you do control
        ↓ yes
4. Institution Track A Institutional Charter (ordinary body), if you are founding one
        ↓
5. Chapter Seventeen §10.1–§10.2 adoption document in that body's custody
   (Forum Track A naming goes on the adoption document)
        ↓
6. Institution Track B functions (oversight, standing-record admin,
   amendment admin, certification steward) — same institution kit
        ↓
7. Forum Track B: CF-13.405 §2 map for all six families
   (hosted/mapped onto existing independent bodies, or in-house)
        ↓
8. CF-13.410 panels · CF-13.415 intake · CF-13.470 staffing · CF-13.450–14 continuity
   CI-11.205 remedy capacity at Chapter Eleven §9.2 parity
        ↓
9. CS-6.350 for systems under that adoption document
```

First adopters use §10.1–§10.2. There are no published existing-adopter joining rules yet.

<a id="41-first-operating-goal-reusable-standard-processes"></a>
### 4.1 First operating goal: Standard Process Recognition

*In plain terms: once certification and forums are really running, the cheapest way to cut repeat work is to assess a shared process once and let many systems rely on it. Make that the first reuse project of the first certification cycle. It is a goal, not a step on the ladder above, and it cannot start earlier.*

**Status.** Outline only. Process support: not binding, not adopted, and it cannot narrow core text. Making it real changes what a certification can rest on, so it needs a core proposal ([Lane D](../../CONTRIBUTING.md#lane-d--core-text-proposals)) touching Chapter Nine and Chapter Thirteen, under [Chapter Seventeen §1 heightened review](../../core_17.000_amendment_ratification.md#1-heightened-review-for-rights-affecting-changes). Until then, adopters use only the component findings in [CS-9.305 §7.10](../../corpus_systems/cs_09.305_system_classification_machinery.md#710-component-findings-within-the-system-classification-record).

**Why this goal first.**

- Repeated processes are where certification work repeats most: appeal and complaint intake, change records, outage and hazard notices, hardship and reconnection intake, access requests, incident reporting.
- [Chapter One §18.6 Standardization](../../core_01.010_stewardship_capacity_principles.md#186-standardization) already makes the common, published form the default. This goal makes that default cheaper to review.
- CS-9.305 and CS-9.310 §7.10 settles first how a part of a system is bounded, shown to be decoupled, and disclosed. The Standard Process Recognition reuses those habits.

**Start only when all four hold.**

1. Steps 5 to 8 above are live: adoption document recorded, certification steward function named, forum families mapped and staffed.
2. At least one certification cycle has used component findings under CS-9.305 and CS-9.310 §7.10, with decoupling verified on the record at least once.
3. Chapter Five defines **Process** with a test (the [project crosswalk](../../project/PROCESS_SYSTEM_INSTITUTION_CROSSWALK.md) has placeholder tests only), and this name, Standard Process Recognition, is distinct from "system alignment certification" and the forum-to-forum sense in [Chapter Thirteen §5](../../core_13.000_forum.md#5-escalation-and-certification).
4. The four seats of [Chapter Eight](../../core_08.000_functional_independence_separation_of_duties.md#2-four-seat-constitutional-requirement) are filled, so the owner of a standard is never its recognizer or the hearer of challenges to it.

**Outline of the mechanism (to be settled).**

- **What is recognized.** A published standard process: a repeatable set of steps, decisions, records, clocks, and handoffs. Not a system, and not one operator's running instance of it. The standard must meet §18.6: published, versioned, open to inspection, contestable, and usable without a fee or dependency that gives its owner control over others.
- **How.** The owner files the standard, its version, and the floors it touches. A forum recognizes the standard once, against those floors, at the **highest** class of any system that will adopt it. Recognition is scope-bound and time-bound, and states a ceiling on adopter class.
- **How adopters use it.**
  - The adopting system carries a conformity statement and a **local-delta note** (local data, staffing, clocks, tools, and every difference from the standard).
  - Its own certification treats the recognition as evidence about the **design** of the process.
  - It must still collect evidence about how the process **runs**. A conformity statement or vendor attestation never substitutes for that ([Chapter Three §2.1.1](../../core_03.000_definition_integrity.md#211-formal-label-and-representation-gaming); [Chapter Nine Part B §8.2](../../core_09.005_system_alignment_certification_record_process.md#82-record-integrity-transparency-and-auditability)).
- **Challenge.** Open at two levels, the standard and each adopter, through the existing contest chain.
- **Reopening.** A new version of the standard, an incident in any adopter, or a credible challenge reopens the recognition and flags every adopter's reliance on it.

**Guardrails carried over from CS-9.305 and CS-9.310 §7.10.**

- The highest class served governs.
- No quiet lowering.
- Parts are tested together, not only one by one.
- No narrowing of scope without a recorded, contestable rationale.
- A change to a standard that touches a Rights Floor is a constitutional question, not the owner's call alone (see the floor-touching test in the [process-ownership draft](../../project/PROCESS_OWNERSHIP_DISPUTE_RULE_DRAFT.md)).
- Recognition of a process is not adoption of the Constitution and not a compliance claim.

**Open questions.**

1. What test separates a process from a component or an institution?
2. What is the recognition called?
3. Can one recognition cover adopters of different classes, or does each class ceiling need its own?
4. Who may challenge a standard, without making steward-only filing a new gatekeeper?
5. How cheap can a local-delta note be without becoming a rubber stamp?
6. Who pays for recognition, so the recognizer is not paid by the owner it recognizes?
7. Which core files change: Chapter Nine Part B §8.1 record contents, and Chapter Thirteen forum roles.

## 5. Body inventory

*In plain terms: required means the owner file already requires it at that mode. Optional means domain- or workload-triggered. Reading a CI or CF file is not the same as staffing an office.*

Companion files bind **when incorporated** under Chapter Eighteen, and **only within the stated adoption scope**. Operations-guide users read them as a guide. They do not staff the offices.

| Family | Operations-guide | Institution Track A | Full adoption (Forum Track B) |
|---|---|---|---|
| **Sentient** | Not founded. Name Forum Track A independent review if you will later record an adoption document | Same: name, do not found | **Required** — distinct family |
| **Technical Forum Domains** | Not founded | Not founded | **Required** — distinct family |
| **Institutional** | Not founded | Not founded | **Required** — distinct family |

| **Integrity** | Not founded | Not founded | **Required** — distinct family |

It does **not** require six in-house benches if an existing independent adjudicative body can be named for that family’s work and the map identifies the concrete forums, benches, or officers ([CF-13.405 §4](../../corpus_forum/cf_13.405_forum_formation_chamber_structure.md#cf-13405-4-minimum-structural-availability-by-family)). The founding crew cannot be the only merits path for any family.

### 5.2 Institution families (CI)

Treat these as **duty homes**, not automatically as separate offices. One body may host more than one lane if independence safeguards are published ([CI-8.205 §2](../../corpus_institutions/ci_08.205_institutional_design_separation_of_powers.md#ci-8205-2-functional-separation-lanes)).

<a id="6-profiles"></a>
## 6. Profiles

*In plain terms: these are order-of-magnitude pictures, not budgets and not floors. Rescale the money to your cost environment. Do not rescale the binding minimums in §2.*

**How the profiles use parity.** The profiles below budget remedy capacity at parity. That is the planning assumption for these estimates. The Chapter Eleven §9.2 departure route in §2 remains available: record the reasons, publish the ratio, and show that remedy commencement and restoration review meet their tier windows. None of the profiles removes that route or permits unfunded lock machinery.

**Estimate convention.** One **loaded FTE** here means one sentient-year of fully loaded compensation in a **2026 high-cost professional** setting (roughly 150–250 thousand currency-units). Figures are order-of-magnitude bands, not quotes. An adopter in a different cost environment should rescale the money and **not** the CJS-18.110 §4 three-sentient rule, the six-family inventory, or the remedy-parity minimum.

**Staff vs N.** *N* is the adopter’s total working headcount. **Staff** in these tables is the slice of *N* (plus contracted independent review) that the constitutional work consumes. If that slice does not fit inside *N* after ordinary product or research work, the profile does not fit.

<a id="7-the-forty-person-lab"></a>
## 7. The forty-person lab

*In plain terms: a forty-person lab can use this Constitution as an operations guide, and can publish a Chapter Five Institutional Charter for work it actually binds. It cannot stand the full companion stack as written, and saying it can is the claim this page exists to refuse.*

Worked row, because this is the case the backlog named.

| | Honest | Not honest |
|---|---|---|
| **N = 40, Class L research tools, no outside dependents** | Profile 1. Optional Profile 2 if they found a research body they can bind. Classify as **L** (or **P** only if effects truly stay inside the private unit) | Calling the lab Slack “Integrity forums.” Claiming Chapter Seventeen adoption |
| **N = 40, Class C evaluation cluster used by other labs** | Profile 1 or 2. Forum Track A = an existing external reviewer. Do not found families | Profile 3 without a named hosted path that filers can actually use |
| **N = 40, Class B deployed system others cannot substitute in time** | Profile 1 as operations-guide **for the duties they can keep**. Full adoption waits until they can bind hosted or in-house family capacity **and** fund remedy under Chapter Eleven §9.2, including its documented-departure conditions. CJS-18.110 §4 already wants fifteen lane sentients at Class B before forums | “We are a small lab, so Class P.” Standing up lock machinery. Relabeling the safety team as six forum families |
| **N = 40, wants in-house six families** | Does not fit Profile 4. Stop | Any sentence that starts “we adopted” and ends with the same forty sentients on every bench |

**Shared administration does not save this row.** CF-13.405 §3 lets families share software and buildings. It does not let one recusal-compromised crew be the Sentient, Institutional, Integrity, and Constitutional merits path at once. Anti-self-judging ([Chapter Thirteen §3](../../core_13.000_forum.md#3-transfer-consolidation-and-coordination--continuity-and-anti-capture)) is why.

**What a forty-person lab should do instead, in order:**

1. Classify honestly ([CS-9.305](../../corpus_systems/cs_09.305_system_classification_machinery.md)).
2. Sit fitness and own-conduct ([`SELF_APPLICATION_GATEWAY.md`](SELF_APPLICATION_GATEWAY.md)).
3. Use steward doors and CS-14.305 §10 logs as operations-guide ([`STEWARD_ENTRY_DOORS.md`](../STEWARD_ENTRY_DOORS.md)).
4. If they can bind a named research or commons scope, publish a Chapter Five Institutional Charter (Institution Track A).
5. Name independent review they do not staff (Forum Track A).
6. If a qualifying body later records an adoption document, take Profile 3 (hosted families) only when those hosted bodies are real. Do not skip to Profile 4.
