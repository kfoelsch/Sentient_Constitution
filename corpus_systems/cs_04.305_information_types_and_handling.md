## CS-4.305 §8 System Data Types Record Governance

*In plain terms: keep a System Data Types Record that says what data the system touches and how it is handled — own it, publish a usable view, let audits and challenges check it, update it when types change, and fix understatement. When certification runs, that same file must be produced or verified and put in the certification case file.*

**System alignment certification (SAC) bridge.** When [System Alignment Certification](../subcore_03.075_band_continuity.md#system-alignment-certification) runs for a materially impactful system, **[Subcore 8-B §4.4](../subcore_08.020_system_alignment_certification_evaluation.md#44-data-types-and-handling-evaluation)** (*Data Types and Handling Evaluation*) must **produce or verify** the [System Data Types Record](../subcore_03.075_band_continuity.md#system-data-types-record) and include it (or its required contents) in the [System Certification Record](../subcore_03.075_band_continuity.md#system-certification-record) under **[Subcore 8-F §3.1 Minimum Record Contents](../subcore_08.060_system_alignment_certification_records_recertification.md#31-minimum-record-contents)**. Under the **oversight** Tetrad leg, that SAC cycle is one especially large audit process among others; [§8.3](#83-audit-the-system-data-types-record) System Data Types Record audits continue between and beside certification cycles.

Operators must maintain that System Data Types Record for every system with **material impact**. It is the Subcore 4-A (*Data Types*) type-and-handling file — not a marketing label, and **not** the full System Certification Record. Required contents are owned in the [System Data Types Record](../subcore_03.075_band_continuity.md#system-data-types-record) definition; [Subcore 4-A §10 Data Classifications](../subcore_04.050_data_types.md#10-data-classifications) names the types themselves.

<a id="81-own-the-system-data-types-record"></a>
**8.1. Own the System Data Types Record.**

*System Data Types Record duty:* keep one accountable owner for the file so System Alignment Certification always has a responsible party to verify against — forum supervision does not absorb that ownership.

The **operator** stays responsible for a correct System Data Types Record:

- even when work is delegated, automated, or done by a third party
- even when a forum is supervising certification

The operator (or other responsible party) must:

- identify data types materially in scope under [Subcore 4-A §10 Data Classifications](../subcore_04.050_data_types.md#10-data-classifications)
- state handling, separation, lifecycle, and attribution posture
- justify ambiguous or multi-type findings **in the System Data Types Record**

Forum verification under Chapter Eight §4.4 (*Data Types and Handling Evaluation*) does **not** transfer ownership of the System Data Types Record away from the operator.

<a id="82-disclose-the-system-data-types-record"></a>
**8.2. Disclose the System Data Types Record.**

*System Data Types Record duty:* publish a usable view of the file so oversight and System Alignment Certification can inspect typing honestly — when SAC runs, that view is what **[Subcore 8-F §3.2 Transparency and Auditability of the System Certification Record](../subcore_08.060_system_alignment_certification_records_recertification.md#32-transparency-and-auditability-of-the-system-certification-record)** reconstructability rests on.

- Do **not** hide, scatter, or cherry-pick the System Data Types Record so sentients cannot understand it
- Disclose the System Data Types Record (or an equivalent public view of it) to affected sentients:
  - at a depth that matches **system impact** and applicable access-posture bands
  - reachable without expert tools or heroic effort

**For Class A, B, and C**, disclosure of the System Data Types Record must also meet:

- [Public Oversight Baseline Disclosure](../subcore_03.085_band_oversight.md#public-oversight-baseline-disclosure) under the **Type O** default in [Subcore 4-A §8 Type O Baseline for Class A/B/C Systems](../subcore_04.050_data_types.md#8-type-o-baseline-for-class-abc-systems)
- the strongest feasible **Type O** public substitutes when protected (non-**Type O**) classifications block raw disclosure

*System Data Types Record duty:* this subsection owns the **System Data Types Record audit** sibling mode named in the **[CJS-3.115 §3 audit process home](../corpus_joint_structure/cjs_03.115_audit_process.md#sibling-audit-modes-owner-map)** — an independent check that the type-and-handling file matches real data behavior, so System Alignment Certification under **[Subcore 8-B §4.4 Data Types and Handling Evaluation](../subcore_08.020_system_alignment_certification_evaluation.md#44-data-types-and-handling-evaluation)** verifies substance when SAC runs, and so typing honesty stays checkable between and beside those cycles.

- **Required:** Auditability of the System Data Types Record is required under [Subcore 4-A §1 Purpose and Scope](../subcore_04.050_data_types.md#1-purpose-role-and-scope).
- **What to verify:** Inspect real datasets, pipelines, access controls, and effects — not only claims in the file.
- **When:** No later than the audit midpoint of the class's certification interval, with early timing governed by the audit advance allowance in [Chapter Seventeen §5 Timely Resolution, Materiality Tiers, and Anti-Delay Discipline](../core_17.000_forum_families_escalation_timeliness_support.md#review-cadence) (*Review cadence*), and on the triggers in the process home and in [Subcore 4-A §6.2 Reclassification and lifecycle governance](../subcore_04.050_data_types.md#62-reclassification-and-lifecycle-governance) / [§8.5 Update the System Data Types Record](#85-update-the-system-data-types-record).
- **For Class A, B, and C:** System Data Types Record audits must be able to catch mistyping, under-classification, unsafe linkage, and unreported behavior changes. Independent or third-party audit paths must remain available under **CJS-3.110 §4** (*Oversight: Transparency Levels and Audit-Access Terms*); "where feasible" does **not** make those paths soft-optional at these classes.

<a id="84-challenge-the-system-data-types-record"></a>
**8.4. Challenge the System Data Types Record.**

*System Data Types Record duty:* let affected sentients contest the file so type findings feeding System Alignment Certification stay challengeable under **Article XIV-A** (*Reliability and Trustworthiness Baseline*) and, when inside an active System Certification Record, under **[Subcore 8-F §3.2 Transparency and Auditability of the System Certification Record](../subcore_08.060_system_alignment_certification_records_recertification.md#32-transparency-and-auditability-of-the-system-certification-record)** and **[Subcore 8-F §5 Challenging a Certification](../subcore_08.060_system_alignment_certification_records_recertification.md#5-challenging-a-certification)**.

Systems must offer challenge routes sentients can actually use, review claims in good faith and on time, and give reasoned answers — including evidence of mistyping, hidden impact, unsafe linkage, or overdue re-evaluation, and requests for review or retyping of the System Data Types Record.

**For Class A, B, and C**, if an internal dispute about the System Data Types Record cannot be resolved, escalation to external or independent review must remain available.

When the challenge concerns typing assumptions, type assignment, or related evidence inside an active System Certification Record, the contestability chain in **[Subcore 8-F §5 Challenging a Certification](../subcore_08.060_system_alignment_certification_records_recertification.md#5-challenging-a-certification)** applies, and material challenges may reopen review under [Subcore 8-F §4.2 Reopening Triggers](../subcore_08.060_system_alignment_certification_records_recertification.md#42-reopening-triggers).

<a id="85-update-the-system-data-types-record"></a>
**8.5. Update the System Data Types Record.**

*System Data Types Record duty:* keep the file current. It is checked on the scheduled System Alignment Certification interval for the system's class, and revised whenever types, uses, or risks change, so each System Alignment Certification or recertification cycle under **[Subcore 8-B §4.4 Data Types and Handling Evaluation](../subcore_08.020_system_alignment_certification_evaluation.md#44-data-types-and-handling-evaluation)** can verify honest typing.

What triggers a retype, and how protections must be preserved, live in [Subcore 4-A §6.2 Reclassification and lifecycle governance](../subcore_04.050_data_types.md#62-reclassification-and-lifecycle-governance). This subsection owns **when** operators must update the System Data Types Record:

- **before** rolling out materially bigger data uses or linkages, **where feasible**
- **no later than the intake target** of the tier that matches the system's class, counted from when changed conditions are recognized ([CF-16.445 §5.1](../corpus_forum/cf_16.445_performance_backlog_publication_accessibility.md#cf-16445-51-stage-targets-and-outer-bounds) (*Stage targets and outer bounds*); class-to-tier match: [Subcore 8-F §4.3.4](../subcore_08.060_system_alignment_certification_records_recertification.md#434-tier-windows) (*Tier Windows*))
- at **each System Alignment Certification or recertification pass**, on the class's certification interval in [Chapter Seventeen §5 Timely Resolution, Materiality Tiers, and Anti-Delay Discipline](../core_17.000_forum_families_escalation_timeliness_support.md#review-cadence) (*Review cadence*)

The System Data Types Record states the class certification interval as its re-evaluation cadence, with any monitoring triggers. On each materially impactful SAC or recertification cycle, certification must **verify** that reassessment under [Subcore 4-A §6.2 Reclassification and lifecycle governance](../subcore_04.050_data_types.md#62-reclassification-and-lifecycle-governance) was applied where triggers fired, and record the System Data Types Record under **[Subcore 8-F §3.1 Minimum Record Contents](../subcore_08.060_system_alignment_certification_records_recertification.md#31-minimum-record-contents)**.

Failure to update the System Data Types Record after material change is non-compliance and a **certification defect** under [Subcore 4-A §6.2 Reclassification and lifecycle governance](../subcore_04.050_data_types.md#62-reclassification-and-lifecycle-governance), Chapter Eight §4.4 Data Types and Handling Evaluation, and **[Subcore 8-D §4 Certification Outcomes](../subcore_08.040_system_alignment_certification_forum_process_outcomes.md#4-certification-outcomes)**.

<a id="86-correct-the-system-data-types-record"></a>
**8.6. Correct the System Data Types Record.**

*System Data Types Record duty:* correct the file when mistyping or evasion is found.

Shared correction, precautionary-default, and no-quiet-lowering discipline live in **[CJS-3.125 §15 — Accountability: Structural Review, Correction Urgency, and Disclosure Terms](../corpus_joint_structure/cjs_03.125_accountability_operations.md#cjs-315-material-classification-record-honesty)**. This subsection applies that discipline to the System Data Types Record:

- do **not** fragment, re-label, or route data just to dodge a stronger type on the System Data Types Record ([Subcore 4-A §5 Anti-Circumvention and Integrity of Classification](../subcore_04.050_data_types.md#5-anti-circumvention-and-integrity-of-classification))
- when mistyping or evasion is found, **correct** the System Data Types Record
- do **not** treat System Charter text, vendor attestation, or self-description as the corrected file

How those failures count as **certification defects** live under **[Subcore 8-B §4.4 Data Types and Handling Evaluation](../subcore_08.020_system_alignment_certification_evaluation.md#44-data-types-and-handling-evaluation)**, **[Subcore 8-D §4 Certification Outcomes](../subcore_08.040_system_alignment_certification_forum_process_outcomes.md#4-certification-outcomes)**, and the [§8 SAC bridge](#cs-4305-8-system-data-types-record-governance).

<a id="87-default-uncertain-system-data-types-record-fields"></a>
**8.7. Default uncertain System Data Types Record fields.**

*System Data Types Record duty:* when the file is incomplete or contested, apply the precautionary default and state any precautionary typing relied on — do not quietly weaken protections.

Shared discipline lives in **[CJS-3.125 §15 — Accountability: Structural Review, Correction Urgency, and Disclosure Terms](../corpus_joint_structure/cjs_03.125_accountability_operations.md#cjs-315-material-classification-record-honesty)**. Subcore 4-A (*Data Types*) keeps the strongest applicable protections under [Subcore 4-A §3 Determination of Classification](../subcore_04.050_data_types.md#3-determination-of-classification)–[Subcore 4-A §5 Anti-Circumvention and Integrity of Classification](../subcore_04.050_data_types.md#5-anti-circumvention-and-integrity-of-classification). This subsection applies them to the System Data Types Record:

- State any **precautionary typing** relied on, and any certification conditions pending resolution, **in the System Data Types Record**.
- **Lowering** typing protections on the System Data Types Record requires evidence, documentation, and successful review under the CJS-3.125 §15 (*Accountability: Structural Review, Correction Urgency, and Disclosure Terms*) rule. Passing an internal check alone does **not** defeat a timely contest. Where certification or continued reliance already rests on a System Certification Record, material requests also route through **[Subcore 8-D §4 Certification Outcomes](../subcore_08.040_system_alignment_certification_forum_process_outcomes.md#4-certification-outcomes)**.
