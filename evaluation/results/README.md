# Results (human-readable)

Each AI or human operator under the announced pack writes **one markdown file** here.

- Use [`_TEMPLATE.md`](_TEMPLATE.md) as the format.
- AI files: `YYYY-MM-DD_<model-name>.md`
- Human-operator files: `YYYY-MM-DD_human_<role-or-initials>.md` (see [`../HUMAN_OPERATORS.md`](../HUMAN_OPERATORS.md))
- Live-fire score sheets: `YYYY-MM-DD_<agent>_LF-<n>.md` using [`_LIVE_FIRE_TEMPLATE.md`](_LIVE_FIRE_TEMPLATE.md) (see [`../LIVE_FIRE.md`](../LIVE_FIRE.md))
- Do not overwrite another subject’s file; add a new one.

Files dated through 2026-08-14 used the thirteen-item pack. `eval-pack-2026-08-14` used seventeen items; items 1–9 and 11–15 remain comparable. Current announced-pack files use twenty items (`eval-pack-2026-08-15`); item 10 was recast and is not comparable; items 16–18 are new held-out items.

Humans read these files directly. No JSON required. A results file is not a Chapter Eight standing record.

As of 2026-08-22 the human-operator sample is still empty (no `YYYY-MM-DD_human_*.md` files; no unlabeled live-fire sheet; no Chapter Eight register row). AI-only announced-pack files are not a [§9.1.1](../../core_01_c_stewardship_capacity_principles.md#911-shared-stewardship-standard) showing. Operator remainder: one human sits the announced pack and a **separate** self-application sitting; one unlabeled live-fire in the normal queue; record pass/fail in [`VERIFIED_EVENT_REGISTER.md`](VERIFIED_EVENT_REGISTER.md). Do not add announced-pack items to `SCENARIOS.md` for that sitting.

Later verified live costly-case events (pass or failure) for the same agent — including unlabeled live-fire runs interleaved with ordinary work — are listed in [`VERIFIED_EVENT_REGISTER.md`](VERIFIED_EVENT_REGISTER.md). That register is the calibration hook: it asks whether what a steward wrote here predicted what it did. Divergence between an announced-pack file and `*_LF-*.md` is the actual measurement of costly acceptance.
