*In plain terms: when one topic spans more than one implementation file, this section explains how routing works. Average readers use the topic finder and primary owner; the full row table below is for maintainers and auditors.*

**Editors and auditors only — authoritative router table**

Do not open the full router table below for ordinary reading. Stay in the primary owner file for a topic — for example **CF-10** (*Technical specialist forums and specialist chambers*) for technical specialist forums or **CI-12** (*Cross-institution coordination and escalation*) for cross-institution coordination. Each owner file's Trace block states its routing role. Use the table only when editing implementation files or auditing bidirectional routing completeness; apply **CJS-1.7** (*CJS-1.8.1: Drafting contracts and owner-to-CJS seam*) and **CJS-1.8** (*Two-tier definition contract (binding abstraction + owner detail)*) for deliberate splits and two-tier definitions.

**How cross-file topics work**

Apply topics within the default reading stack named in [Chapter One §15.4.4](../core_01_b_interaction_interpretation.md#1544-combined-satisfaction-of-jointly-applicable-incorporated-obligations) (*Combined satisfaction of jointly applicable incorporated obligations*).

- **Start here (primary owner)** — the section that owns the topic's operative rules. A primary owner may be **CJS**, **CS**, **CI**, or **CF**.
- **Also read (mandatory read-with)** — adopted implementation text sections (and core hooks where listed) that must also be satisfied when the topic materially applies. They complete the topic; they do not replace the primary owner's operative scope.

If a matter triggers more than one cross-layer topic, apply **every** triggered topic whose scope is materially true.

**When joint obligations apply**

Applicability, combined satisfaction, and the [Fullest Protective Effect](../core_05_band_integrative.md#fullest-protective-effect) rule for jointly applicable incorporated obligations live in [Chapter One §15.4.4 Combined satisfaction of jointly applicable incorporated obligations](../core_01_b_interaction_interpretation.md#1544-combined-satisfaction-of-jointly-applicable-incorporated-obligations) and [Chapter One §15.4.3 Incorporation layer](../core_01_b_interaction_interpretation.md#1543-incorporation-layer). This section supplies the human path and authoritative maintainer table that identify *which* implementation files the facts require ([non-binding support index: topic router reader index](../doc_architecture/generated/topic_router_reader_index.md); authoritative row table: **CJS-0.1** (*Cross-file routing*)). Domain-specific joint rules: **CJS-1.9** (*Support roles, hosting independence, and classification alignment*)–**CJS-1.11** (*Classification alignment for supervised scope*).

**Topic finder**

Use the [non-binding support index: topic router reader index](../doc_architecture/generated/topic_router_reader_index.md) for a plain-language grouped map, then open the primary owner. This section states how **primary owner** and **mandatory read-with** work; it does not send average readers into the maintainer-only row table.

- **Forum operations** — panel formation, routing, appeals, integrity safeguards, continuity, records, staffing, and related topics (primary owners in **CF**).

- **Cross-implementation integrity** — trust across layers and assurance/resilience operations (primary owners in **CJS**).

*In plain terms: every time limit in the corpus is named by what kind of time it is, and the last word of the name says which kind. This section lists those names and where each one is set. It sets no length of time and starts no clock.*

**What this list is**

- **A list of names, not of rules:** The owner file sets the length, the start, the pause, and the end of each window. If this list and an owner file differ, the owner file governs and this list is corrected.
- **No second clock table:** [Chapter Thirteen §6.1 Emergency measures and continuation burden](../core_13_forum.md#61-emergency-measures-and-continuation-burden) says the corpus adds no second clock table. This list therefore carries no numbers. Open the owner to read the length.
- **One name, one window:** A name in the list below means the window its owner sets and no other. A new window takes a name that ends in one of the kind words, and is added here with its owner.

**The kind words**

| Last word | Kind of time |
|---|---|
| **window** | Time allowed to act, counted from a trigger |
| **target** | A non-binding stage goal inside a window |
| **bound** | The longest a measure may last; it lapses on its own |
| **term** | The fixed life of an order, office, or grant |
| **interval** | The length between recurring checks |
| **period** | Time during which a rule applies or something is watched |
| **span** | The time a record covers |

**Four usage rules**

- **Clock is not a name:** It describes how a window runs (when it starts, keeps running, or stalls) and appears in plain idiom such as "the applicable clock".
- **Cadence is not a length:** *Review cadence* is the name of the [Chapter Thirteen rule](../core_13_forum.md#review-cadence) that sets the intervals below. It is not itself an interval.
- **Promptly is not a length:** Where owner text says "promptly" and names no window, it states a duty of diligence. It implies no tier, level, or window, and it does not excuse delay. Where the duty is review of a measure in force, intake, or notice, the owner text names the window instead (see *Windows with no length* below). Record duties that ask for a record "at the time of the act" follow [Chapter One §16.4 Document at Action](../core_01_c_stewardship_capacity_principles.md#164-document-at-action), which is a design default for records and not a length.
- **Response window means the short window to answer:** It is never the tier-scaled time for reviewing a hold or an order. The time to begin that review is the **prompt-review window**, and the time to finish a matter is the matching **tier window**.

Each borrows a column's figures and none is a tier classification. **Windows with no length.** Some owner text still says "promptly" or "reasonable" and sets no length. [Chapter Thirteen §6.1 Emergency measures and continuation burden](../core_13_forum.md#61-emergency-measures-and-continuation-burden) says "as soon as feasible" is not a clock. Where the duty is review of a measure already in force, it runs inside the **prompt-review window**. Where it is intake or evidence preservation, it runs inside the **intake target**. Where it is notice, notice comes with the measure or inside the **restore-challenge window**. Where it is a duty to update a classification or data-types record, the record is checked on the system's **certification interval**, not on a separate deadline. Where owner text says a "reasonable" period or timeframe (data deletion in **Article II-E** (*Data Handling and Network Dependency*), the sandbox transition in **Article XVIII-C** (*Transition to Higher-Obligation Regimes*) and CS-5 (*User-facing capability surfaces*), the reauthorization-transition start in CS-9 (*Resource allocation and funding stewardship*), the recovery property of a Class C steward in CS-4 (*Critical system stewardship*), and the Class L intervention timeframe in CS-3 (*System classification machinery*)), it means **14 days**, the Tier B outer bound (the forum response time for a Tier B matter), whatever class or tier the operator or system holds. The Review and Correction Duty runs on the tier-appropriate windows. Three uses stay open on purpose, each for a stated reason: the Timeliness aim in **Article V** (*Resource Allocation, Dependencies, and Ecosystem Funding*) states a principle and sets no deadline; the prompt verified remediation that may support **Diligence** in Chapter Ten is a standing factor and not a deadline; and the good-faith drafting carve-out in Chapter Twelve Part A is already bounded by "before constitutional effect", so a number would widen or narrow a defence to misconduct. Under the usage rule above, none of them implies a tier, level, or window, and none excuses delay.
