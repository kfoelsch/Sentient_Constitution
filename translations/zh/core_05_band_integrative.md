### 整合：独立用语

<a id="non-compliance"></a>

#### 不合规

<details>
<summary><strong><span style="color: #2563eb;">溯源</span></strong></summary>

- 上游：[第二章 §1 — 宗旨与角色](core_02_definition_structure.md#1-purpose-and-role)；[第二章 §2 定义完整性要求](core_02_definition_structure.md#2-definition-integrity-requirement)；[第三章 §2 — 来自可观察系统行为的不合规](core_03_definition_integrity.md#2-non-compliance-from-observable-system-behavior)。
- 下游：[第四章 §§1 与 4 — 排他执行与负担分配；合规证据标准](core_04_burden_traceability_verification.md#1-exclusive-enforcement-and-burden-allocation)；[第八章 — 贡献、违规与轨迹模型](../../core_08_standing_assessment.md#chapter-eight-compliance-violation-and-standing-model)；[不合规认定画像](core_05_band_accountability.md#non-compliance-finding-profile)。
- 一并阅读：[第一章 §11.3 错位检测](core_01_c_stewardship_capacity_principles.md#113-misalignment-detection) 与 [§11.4 错位纠正与俘获响应](core_01_c_stewardship_capacity_principles.md#114-misalignment-correction-and-capture-response) — **宪法错位**是尽责管理与激励上的偏离；它不是**不合规**的替代标签；[剩余风险 / 错位](core_05_band_continuity.md#residual-risk--misalignment) — 缓解之后的有界剩余风险；[系统对齐认证](core_05_band_continuity.md#system-alignment-certification-constitutional) — 第七章中的认证桥，不是一般不合规裁决。

</details>

<br>

*用直白的话说：当一项定义的要求在实践中未被满足时，系统或定义即不合规 — 按它实际做什么、产出什么来判断，经由适用的测量，当系统作为整体在运行时。*

- **它是什么**
  - **范围内：** 一项定义的要求未被满足的状态。那意味着：
    - 其本体（O）、测量（M）、评估（A）与合规（C）各部分未被联合满足；
    - 在同一功能系统范围上；以及
    - 在同一评价条件下。

    收窄一项定义完整含义、评估或真实世界要求的规避行为，在[第三章](core_03_definition_integrity.md#chapter-three-definition-integrity-evasion-and-non-compliance)下计为不合规。同一纪律适用于单一叶定义之外、由第二至四章统管解释、证据与可追溯性的宪法义务。
  - **范围外：**
    - 尽责管理与激励层上的**宪法错位**（第一章 §11）；
    - [剩余风险 / 错位](core_05_band_continuity.md#residual-risk--misalignment) 作为缓解之后的有界风险状态；
    - 第七章下的系统对齐认证地位；以及
    - 第八章违规轴槽位标签（那些给经核实认定分类，并不重新定义一项定义是否被满足）。
<a id="non-compliance-a"></a>
- **如何测量与评估**
  - **主要测量：** 整合实质性 — [实质性认定](core_05_band_oversight.md#materiality-determination) 在[实质利害](core_00_preamble.md#material-stake)下缩放义务强度；不是单独的测量类别。

    **主要评估：** 按以下各项判断：
    - 可观察行为；
    - 结果；以及
    - 在完整功能系统条件下跟踪它们的测量。

    联合适用全部 O、M、A 与 C 部分。名称、纸面结构、所宣称意图或形式类别不作决定。在判定行为或规避是否计为不合规时，适用[第三章 §1](core_03_definition_integrity.md#1-definition-integrity-and-anti-evasion-constraints) 与 [§2](core_03_definition_integrity.md#2-non-compliance-from-observable-system-behavior)。
<a id="non-compliance-c"></a>
- **必须成立什么**
  - **主要失败：** 在下列情形下仍把系统、行动者或定义当作合规：
    - 任何所要求的 O、M、A 或 C 部分失败；
    - 规避收窄了该定义；或
    - 所宣称结构或意图被优先于可观察行为与效果。
  - **次要失败：** 在[第四章](core_04_burden_traceability_verification.md#1-exclusive-enforcement-and-burden-allocation)举证责任或证据充分性未被满足之处，默认当作合规。

<a id="constitutional-contract-layer"></a>

#### 宪法契约层

<details>
<summary><strong><span style="color: #2563eb;">溯源</span></strong></summary>

- 下游：原则：[序言 §3.3 治理层纪律](core_00_preamble.md#33-governance-layers)；[第一章 §5 自由](core_01_a_values_principles.md#5-freedom-bounded-agency)。
- 主责底线：[第十二章：宪法契约、正当性、授权与尽责管理](../../core_12_governance.md#chapter-twelve-constitutional-contract-legitimacy-authorization-and-stewardship)；[Article IX-C：治理参与与投票权资格](../../core_06_rights_part_b.md#article-ix-c-governance-participation-and-voting-entitlement)。
- 簇组件：[*宪法契约层与基础宪法选择*](core_05_band_integrative.md#constitutional-contract-layer)
- 一并阅读：[基础宪法选择](core_05_band_integrative.md#foundational-constitutional-choice)、[约束性受影响方选择](core_05_band_participation.md#binding-stakeholder-choice-cluster)、[受影响方地位与权重](core_05_band_participation.md#stakeholder-status-and-weight-cluster)、[治理](core_05_band_accountability.md#governance)。
- 层：**宪法契约层（CCL）** — 谁可以治理、凭何种正当性机制、在何种持久条款之下。有别于**受影响方的系统参与（SSP）**。

</details>

<br>

*用直白的话说：这一层回答谁可以治理、凭何种正当性、在何种持久条款之下 — 不是普通咨询、使用或品牌。*

- **它是什么**
  - **范围内：** 治理权威本身的授权层。它覆盖：
    - 谁可以治理；
    - 凭何种正当性机制；以及
    - 在何种范围与持久条款之下。

    它包括：
    - [基础宪法选择](core_05_band_integrative.md#foundational-constitutional-choice)；
    - [已记载正当性机制](../../core_12_governance.md#1-authorization-and-legitimacy-of-governing-authority)，于 [第十二章 §1.1](../../core_12_governance.md#11-mechanism-families-auditability-and-pluralism)；
    - [采纳](../../core_15_amendment_ratification.md#10-ratification-and-adoption) 与 [再授权](../../core_12_governance.md#11-mechanism-families-auditability-and-pluralism) 规则（[第十二章 §1.3](../../core_12_governance.md#13-recall-class-pathways-and-mid-cycle-transfer-guardrails)；[第十六章 §4](../../core_16_incorporation.md#4-adoption-framing-and-scope-of-authority)）；以及
    - 构成或持久重组治理权威的[政治平等底线](../../core_12_governance.md#41-entitlement-and-eligibility) — 有资格的感知者在该层有平等声音（[Article IX-C](../../core_06_rights_part_b.md#article-ix-c-governance-participation-and-voting-entitlement)）。
  - **范围外：**
    - 普通受影响方咨询；
    - 操作性参与；
    - 系统使用、品牌或市场存在本身；
    - 结构与过程已经获得授权之后的普通领域治理；以及
    - 普通[受影响方权重](core_05_band_participation.md#stakeholder-weight) — 给受影响更深者更多声音 — 被用来设定创立或再授权投票（[序言 §3.3 治理层纪律](core_00_preamble.md#33-governance-layers)）。
  - **操作性家园：** [第十二章](../../core_12_governance.md#chapter-twelve-constitutional-contract-legitimacy-authorization-and-stewardship) 陈述本层有约束力的授权、正当性与尽责管理规则。
  - **权利底线：** [Article IX-C](../../core_06_rights_part_b.md#article-ix-c-governance-participation-and-voting-entitlement)（*治理参与与投票权资格*）陈述那些第十二章规则不得收窄的平等参与资格。
<a id="constitutional-contract-layer-a"></a>
- **如何测量与评估**
  - **主要测量：** [问责测量族](core_05_apex_accountability_leg.md#accountability-measurement-family) — *奖惩结构、市场力量与应答义务是否让义务保持真实？* 在此处用来问：所主张的治理权是否落在一份真实的宪法契约上 — 已记载的正当性、平等的创立声音，以及与本宪法保持对齐的持久条款 — 而不只是规模、人气或市场触及。

    **主要评估：**
    - 问一问该事项是否是宪法契约层问题：授权谁治理、凭何种正当性机制、在何种持久条款之下。那一功能标记本层 — 不是系统有多大、多吵或用得有多广。
    - 核验该契约的宪法对齐：所主张的权威必须匹配一项[已记载正当性机制](../../core_12_governance.md#1-authorization-and-legitimacy-of-governing-authority)、基础选择适用之处的[政治平等底线](../../core_12_governance.md#41-entitlement-and-eligibility)，以及使治理权在本宪法下保持应答义务的尽责管理与权利底线义务（[第一章 §11.1 对齐要求](core_01_c_stewardship_capacity_principles.md#111-alignment-requirement)）。
    - 适用[序言 §3.3 治理层纪律](core_00_preamble.md#33-governance-layers)：把创立授权与已获授权系统内部的普通受影响方参与分开。
    - 不得把沉默、仅仅使用一个系统、市场存在或品牌当作宪法契约，或当作被治理的同意。
<a id="constitutional-contract-layer-c"></a>
- **必须成立什么**
  - **主要失败：**
    - 把受影响方咨询、操作性参与、系统使用、品牌、市场存在或按影响加权的受影响方过程，当作已记载宪法授权的替代；
    - 在[基础宪法选择](core_05_band_integrative.md#foundational-constitutional-choice)要求政治平等底线之处，用按影响加权的受影响方投票来构成或持久重组治理权威；或
    - 把宪法授权当作消除已获授权系统或有界决定域内部的受影响方参与、代表、[可质疑性](core_05_band_accountability.md#contestability) 或 [正当程序](core_05_band_accountability.md#due-process-constitutional) 义务（[序言 §3.3](core_00_preamble.md#33-governance-layers)）。

#### 基础宪法选择

<details>
<summary><strong><span style="color: #2563eb;">溯源</span></strong></summary>

- 下游：原则：[第一章 §5 自由](core_01_a_values_principles.md#5-freedom-bounded-agency)；[6. 过程冲突解决](#6-process-conflict-resolution)。
- 主责底线：[第十二章第一章 §4.1](../../core_12_governance.md#41-entitlement-and-eligibility)（*基础宪法选择的政治平等底线*；*持久政治声音底线*）；[Article IX-C：治理参与与投票权资格](../../core_06_rights_part_b.md#article-ix-c-governance-participation-and-voting-entitlement)。
- 簇组件：[*宪法契约层与基础宪法选择*](core_05_band_integrative.md#constitutional-contract-layer)
- 一并阅读：[宪法契约层](core_05_band_integrative.md#constitutional-contract-layer)、[受影响方代表与权重限度（约束性受影响方选择）](core_05_band_participation.md#stakeholder-representation-and-weight-limits-binding-stakeholder-choice)、[约束性受影响方选择](core_05_band_participation.md#binding-stakeholder-choice-cluster)、[程序公平](core_05_band_participation.md#procedural-fairness-constitutional)。
- 层：**宪法契约层（CCL）**。有别于已获授权系统内部的**受影响方的系统参与（SSP）**。

</details>

<br>

*用直白的话说：关于谁持有治理权威、凭何种机制、在何种持久条款之下的决定 — 在那一创立层上一个感知者一份声音，不是按影响加权的普通受影响方投票。*

- **它是什么**
  - **范围内：** 其对象就是治理权威本身之授权的治理决定：
    - 谁持有它；
    - 何种治理机制适用；以及
    - 该权威的范围与持久条款。

    这属于[宪法契约层](core_05_band_integrative.md#constitutional-contract-layer)。
    - 主责：[第十二章第一章 §4.1](../../core_12_governance.md#41-entitlement-and-eligibility)。
    - 权利层指针：[Article IX-C](../../core_06_rights_part_b.md#article-ix-c-governance-participation-and-voting-entitlement)（*治理参与与投票权资格*）。
    - 在[感知性不排除](core_05_band_participation.md#sentience-non-exclusion)下适用。
  - **范围外：**
    - 某一领域已经拥有获授权治理结构与过程之后的普通按影响加权受影响方决定 — 受影响的感知者通过[受影响方](core_05_band_participation.md#stakeholder)识别与[受影响方权重](core_05_band_participation.md#stakeholder-weight)（包括 **Article XI**（《受影响方的系统参与、代表与正当程序》）约束）按受影响程度得到缩放的声音，而不是通过等权创立计票规则；以及
    - 并不授权或持久重组该权威的例行运营或政策选择。
<a id="foundational-constitutional-choice-a"></a>
<a id="foundational-collective-choice-constitutional-a"></a>
- **如何测量与评估**
  - **主要测量：** [问责测量族](core_05_apex_accountability_leg.md#accountability-measurement-family) — *奖惩结构、市场力量与应答义务是否让义务保持真实？* 在此处用来问：平等的创立声音在实践中是否仍保持真实 — 不被财富买走、不被市场力量扭曲、也不被按影响加权的受影响方投票替换。

    **主要评估：**
    - 当一项决定关乎谁可以治理、凭何种机制或在何种持久条款之下时，把它当作基础性的 — 不是因为一次投票或一项政策选择有很大的短期效果。
    - 读[序言 §3.3 治理层纪律](core_00_preamble.md#33-governance-layers)。
    - 基础问题不得在[受影响方代表与权重限度（约束性受影响方选择）](core_05_band_participation.md#stakeholder-representation-and-weight-limits-binding-stakeholder-choice)下被再路由为高影响加权选择。
    - 适用[感知性不排除](core_05_band_participation.md#sentience-non-exclusion)。
    - 不得按基质类别（生物、合成或数字种类）、日历年龄或谱系（祖先、物种或派生）给予更多或更少的创立声音。
    - 对任何被援引来剥夺参与资格的取消资格，适用[程序公平](core_05_band_participation.md#procedural-fairness-constitutional)。
<a id="foundational-constitutional-choice-c"></a>
<a id="foundational-collective-choice-constitutional-c"></a>
- **必须成立什么**
  - **主要失败：** 把基础问题在[受影响方代表与权重限度（约束性受影响方选择）](core_05_band_participation.md#stakeholder-representation-and-weight-limits-binding-stakeholder-choice)规则下再路由为高影响加权选择，以致击败授权层上的平等参与。
  - **次要失败：** 把影响加权嵌进正当性机制设计，使该机制逃出政治平等底线。
  - **第三失败：**
    - 把轨迹丧失用作持久政治声音取消资格向量，且未能通过第十二章第一章 §8.1 *持久政治声音底线* 检验，但第十章反宪法不当行为在完全返还之前的最终扣留除外；或
    - 基质类别、日历年龄或谱系的参与权重因素（[感知性不排除](core_05_band_participation.md#sentience-non-exclusion)）。

#### 创新奖赏与反圈占

*用直白的话说：奖赏真正的发明与有用的创造 — 但不要让那份奖赏硬化成对修理、再利用、研究或公共利益使用的持久锁定。*

- **它是什么**
  - **范围内：** 奖赏在实质上新颖且对社会有用的发明、研究、建造与创造的宪法规则 — 而不让那份奖赏变成持久圈占。
    - 宪法依据：在[第一章 §11.1.3](core_01_c_stewardship_capacity_principles.md#1113-stewardship-and-operator-application) 下，奖赏可以正当地跟踪[生产能力](core_05_band_continuity.md#productive-capacity-constitutional) 与 [宪法效率](core_05_band_continuity.md#constitutional-efficiency)；[可避免负担](core_05_band_continuity.md#avoidable-burden) 防止奖赏空转事务、囤积或不服务任何宪法宗旨的圈占摩擦。
    - 奖赏可以承认贡献、开发负担与披露。
    - 它可以包括暂时排除，仅当该排除是：
      - 狭窄的；
      - 有时限的；
      - 可审查的；以及
      - 经正当化的。
    - 归属不是排除；任何排除结束后，信用与来源历史仍可存续。
    - 凡奖赏结构可能影响[福祉](core_05_band_continuity.md#wellbeing)、[安全（约束）](core_05_band_continuity.md#safety-constraint)、[真理（宪法约束）](core_05_band_oversight.md#truth-constitutional-constraint) 或 [有意义的能动性](core_05_band_participation.md#meaningful-agency) 之处，即予适用。
  - **依赖于：** [必要性](core_05_band_accountability.md#necessity)、[相称性](core_05_band_accountability.md#proportionality) 与 [系统性锁定套牢](core_05_band_continuity.md#systemic-lock-in) — 构成性限度。任何排除必须经必要性与相称性正当化，并且对使用的控制不得硬化成：
    - 永久稀缺；
    - 系统性锁定套牢；或
    - 压制修理、互操作、学习、安全工作、诚实披露或下游实验。
  - **范围外：**
    - 无排他控制的归属、信用或来源本身；以及
    - 不限制修理、再利用、互操作、研究或公共利益实施的普通承认或品牌。

- **如何测量与评估**
  - **主要测量：** [问责测量族](core_05_apex_accountability_leg.md#accountability-measurement-family) — *奖惩结构、市场力量与应答义务是否让义务保持真实？* 在此处用来问：对发明的奖赏是否仍是真实贡献奖赏 — 而不是对修理、再利用、研究或公共利益使用的持久锁定。

    **主要评估：** 按此顺序评价创新奖赏主张：
    1. **识别真实贡献：** 评估开发负担、披露充分性与公共利益。奖赏要求真实贡献，以及足以支持独立理解、审计与日后实施的披露 — 仅受经正当化的暂时限度约束。
    2. **把归属与排除分开：** 主张者可在任何排除期限结束后保留信用、来源与承认。这些利益本身并不正当化对修理、再利用、兼容、研究、教育、迁移或公共利益实施的控制。
    3. **检验必要性与相称性：** 问一问排他究竟是否需要。问一问同样或更大的公共利益能否通过限制更少的奖赏工具获得。任何排除必须在[必要性](core_05_band_accountability.md#necessity) 与 [相称性](core_05_band_accountability.md#proportionality) 下狭窄、有时限且可审查。
    4. **按语境缩放：** 按以下各项调整分析：
       - 系统类别；
       - [依赖](core_05_band_continuity.md#dependency)；
       - 协调权力；
       - 互操作负担；以及
       - [可逆性](core_05_band_continuity.md#reversibility-constitutional)。

       依赖、杠杆或不可逆性越强，反对排除的推定就越强。
    5. **偏好非垄断机制：** 凡排他可预见地会造成锁定套牢、反竞争囤积，或对下列各项的实质伤害之处，使用奖金、征费、池化许可、公共买断、强制准入或类似工具：
       - Class A、Class B 或 Class C 系统；
       - 生存关键领域；
       - 标准制定职能；或
       - 基础知识。
    6. **适用可反驳推定：** 强排除在下列各项上面对反对它的可反驳推定：
       - 药品与公共卫生必需品；
       - 生存关键基础设施；
       - 基础科学知识；
       - 核心互操作标准；以及
       - 宪法安全、审计或合规机制。

- **必须成立什么**
  - **主要失败：** 持久或无期限排除；战略性不使用；钓饵滥权；人为稀缺；或实质阻断下列各项的奖赏主张：
    - 修理；
    - 安全测试；
    - 互操作；
    - 迁移；
    - 教育；
    - 研究；
    - 诚实审视；或
    - 公共利益实施。
  - **次要失败：** 对一项[依赖](core_05_band_continuity.md#dependency)关键创新继续排除，而无：
    - 按分类缩放的收紧；
    - 转为保全通路的奖赏；或
    - 在 [corpus_systems.md](../../corpus_systems.md)，CS-3 — 系统分类与处置下到期终止。
  - **第三失败：**
    - 造成[系统性锁定套牢](core_05_band_continuity.md#systemic-lock-in)、反竞争瓶颈、实质[伤害](core_05_band_accountability.md#harm)，或在限制更少的奖赏工具同样有效或更好时对单一主张者的可避免依赖的排除；或
    - 建立在隐瞒、不充分披露，或超出第一章与第六章所能正当化的借口性限制之上的奖赏主张。

    - 并不可预见地塑造行动者、运营者或组件行为的普通报酬或目标。
  - **实施路由：** 整系统层面的完整激励分析，仍由经第十五章纳入的、关于激励对齐与机制完整性的已采纳实施要求统管。本定义为一并调用激励的相互依赖层上的宪法合规判定提供追溯 — 它不重述或挪走那些操作性规则。具实质影响场所的操作性预期出现在：
    - `corpus_systems.md`（CS-4 — 关键系统尽责管理，包括按激励缩放的治理）；以及
    - `corpus_institutions.md`（机构尽责管理与激励对齐要求）。

- **如何测量与评估**

    **主要评估：** 跨越延迟与汇总效果评估对齐，而不只是即时或局部产出 — 包括对下列各项的效果：
    - [安全（约束）](core_05_band_continuity.md#safety-constraint)；
    - [风险](core_05_band_continuity.md#risk)；
    - [伤害](core_05_band_accountability.md#harm)；以及
    - [有意义的能动性](core_05_band_participation.md#meaningful-agency)。

    当本簇下一项更具体的子题具有实质利害时，跟随该子题的评估路径。
  - **次要测量：** [福祉](core_05_band_continuity.md#wellbeing)、[安全（约束）](core_05_band_continuity.md#safety-constraint)、[认识完整性](core_05_band_oversight.md#epistemic-integrity) 与 [有意义的能动性](core_05_band_participation.md#meaningful-agency) — 即使名义目标看似被满足，仍可击败对齐的并行测量。

    **第三评估：** 纳入[替代指标偏离](core_05_band_oversight.md#proxy-divergence)。把利用下列各项与对[福祉](core_05_band_continuity.md#wellbeing)、[安全（约束）](core_05_band_continuity.md#safety-constraint) 或 [认识完整性](core_05_band_oversight.md#epistemic-integrity) 具有实质性的真实结果之间缺口的任何奖赏路径、目标或治理信号，计为激励对齐输入：
    - 替代指标；
    - 度量；或
    - 形式合规指示器。

  - **主要失败：** 在无下列各项的情况下，可预见地削弱第一章价值的持续激励：
    - 缓解；
    - 披露；或
    - 可行覆盖。
  - **次要失败：**
    - 未能主动检测、披露并纠正此类错位（第一章 §11.3–§11.4）；

    - 主张宪法激励对齐，同时忽略统管受审系统激励完整性的已采纳实施要求。
  - **第三失败：** 在[替代指标偏离](core_05_band_oversight.md#proxy-divergence) 可被合理观察之处，把替代指标或合规指示器满足当作决定性。

##### 激励对齐 — 基线宪法对齐

- **它是什么**
  - **范围内：** 作用于行动者、运营者或构成组件的激励结构 — 奖赏路径、目标、治理信号，以及可预见地跨越延迟与汇总效果塑造行为的可比结构。
  - **依赖于：** [安全（约束）](core_05_band_continuity.md#safety-constraint)、[真理（宪法约束）](core_05_band_oversight.md#truth-constitutional-constraint)、[信任](core_05_band_continuity.md#trust) 与 [有意义的能动性](core_05_band_participation.md#meaningful-agency) — 构成性对齐目标。激励结构必须与这些限度对齐，并与有助于经正当化[信任](core_05_band_continuity.md#trust) 的系统稳定对齐。
  - **范围外：** 不针对安全、真理、信任或有意义的能动性限度塑造延迟或汇总行为的短时域局部奖赏微调。
  - **一并阅读：** 凡分数或度量可能对照那些限度掩盖真实结果之处，一并阅读[替代指标偏离](core_05_band_oversight.md#proxy-divergence) — 主责在[激励对齐](#incentive-alignment) 第三层级。

    **主要评估：** 在上文**依赖于**所述限度下，跨越延迟与汇总效果适用簇头的主要评估。
- **必须成立什么**
  - **主要失败：** 可预见地把延迟或汇总行为推向上文所述安全、真理、信任或有意义的能动性限度相反方向的激励结构。

##### 激励对齐 — 战略、规模化与对抗性评价

<details>
<summary><strong><span style="color: #2563eb;">溯源</span></strong></summary>

- 簇组件：[激励对齐、替代指标完整性与或有结算](core_05_band_integrative.md#incentive-alignment-semi-independent)
- 一并阅读：[激励对齐](core_05_band_integrative.md#incentive-alignment)；[对抗性、规模化与被利用条件](core_05_band_oversight.md#adversarial-scaled-and-exploited-conditions)。

</details>

<br>

*用直白的话说：在系统博弈、规模、协调与故意误用下核验激励 — 而不只是在客气的实验室条件下。*

- **它是什么**
  - **范围内：** [对抗性、规模化与被利用条件](core_05_band_oversight.md#adversarial-scaled-and-exploited-conditions) 下的激励对齐评价，包括：
    - 系统博弈；
    - 跨实例协调；
    - 高规模部署 — 行为或效果可能不同于小规模或理想实验室使用的体量、并发或触及；以及
    - 适应性或故意误用。
  - **范围外：** 理想实验室测试或一次性误用轶事 — 那些落在压力、规模、协调或故意利用之外。
- **如何测量与评估**
  - **主要测量：** [问责测量族](core_05_apex_accountability_leg.md#accountability-measurement-family) — *奖惩结构、市场力量与应答义务是否让义务保持真实？* 在此处用来问：激励在系统博弈、规模、协调与故意误用下是否仍能成立 — 而不只是在客气的实验室条件下。

    **主要评估：** 纳入[对抗性、规模化与被利用条件](core_05_band_oversight.md#adversarial-scaled-and-exploited-conditions)。
- **必须成立什么**
  - **主要失败：** 主张激励对齐，同时从评价中省略具实质相关性的对抗性、规模化或被利用条件 — 包括把下列任何一项当作压力、规模、协调或故意利用的替代：
    - 理想实验室测试；或
    - 一次性误用轶事。

##### 激励对齐 — 或有请求、机会博弈与事件合约市场

<details>
<summary><strong><span style="color: #2563eb;">溯源</span></strong></summary>

- 下游：原则：[第一章 §11.5 或有请求、机会博弈与事件合约市场](core_01_c_stewardship_capacity_principles.md#115-contingent-claims-games-of-chance-and-event-contract-markets)。
- 簇组件：[激励对齐、替代指标完整性与或有结算](core_05_band_integrative.md#incentive-alignment-semi-independent)
- 一并阅读：[激励对齐](core_05_band_integrative.md#incentive-alignment)；[或有请求、事件合约市场、机会博弈与内部人优势](core_05_band_accountability.md#contingent-claims-games-of-chance-and-event-contract-markets-semi-independent)。

</details>

<br>

*用直白的话说：赌注、预测市场与基于机会的支付，不得奖赏不法伤害、内部人权力，或对公共或信义决定的扭曲。*

- **它是什么**
  - **范围内：** [或有请求](core_05_band_accountability.md#contingent-claim) 结构，包括[机会博弈](core_05_band_accountability.md#game-of-chance) 与 [事件合约市场](core_05_band_accountability.md#event-contract-market) 形式，凡具有实质相关性之处。
  - **范围外：**
    - 不是或有请求、机会博弈或事件合约形式的普通固定义务合同或交换；或
    - 作为市场信号本身的结算价格或赔率 —
    那些落在本家园的或有结算纪律之外；价格与赔率本身不是真理或合规判定。
<a id="incentive-alignment-contingent-claims-games-of-chance-and-event-contract-markets-a"></a>
- **如何测量与评估**
  - **主要测量：** [问责测量族](core_05_apex_accountability_leg.md#accountability-measurement-family) — *奖惩结构、市场力量与应答义务是否让义务保持真实？* 在此处用来问：赌注、预测市场与基于机会的支付是否避免奖赏不法伤害、内部人权力，或对公共或信义决定的扭曲。

    **主要评估：** 此类系统必须满足[第一章 §11.5](core_01_c_stewardship_capacity_principles.md#115-contingent-claims-games-of-chance-and-event-contract-markets)，包括：
    - 对感知者可以押注或据以结算的底层事件适用[必要性](core_05_band_accountability.md#necessity) 与 [相称性](core_05_band_accountability.md#proportionality)；
    - 保持结果裁定公平且独立 — 凡可行即使用不止一个来源，并保持争议路径对质疑开放；
    - 限制任一行动者可以承担的集中、杠杆与暴露，按感知者与更广系统有多脆弱来缩放；
    - 在协调与高规模条件下核验误用；以及
    - 把价格与赔率只当作市场信号 — 本身不是真理或合规的证明；使用与其他高影响决定相同的证据标准。
  - **次要测量：** [风险](core_05_band_continuity.md#risk)、[解决路径俘获](core_05_band_accountability.md#capture-of-resolution-pathways) 与 [内部人优势](core_05_band_accountability.md#insider-advantage) — 即使 §11.5 设计控件看似被满足，仍可击败或有结算对齐的完整性叠加。

    **次要评估：** 在核验主要测量时，问一问这些叠加是否仍显示错位：
    - 结果操纵[风险](core_05_band_continuity.md#risk)；
    - [解决路径俘获](core_05_band_accountability.md#capture-of-resolution-pathways)；或
    - [内部人优势](core_05_band_accountability.md#insider-advantage) 或其他特权信息路径。
<a id="incentive-alignment-contingent-claims-games-of-chance-and-event-contract-markets-c"></a>
- **必须成立什么**
  - **主要失败：** [或有请求](core_05_band_accountability.md#contingent-claim)、[机会博弈](core_05_band_accountability.md#game-of-chance) 或 [事件合约市场](core_05_band_accountability.md#event-contract-market) 内部可预见地奖赏下列各项的结算结构：
    - 不法伤害；
    - 来自非公开权力的腐败优势；或
    - 对信义或公共决定的实质扭曲

    而无相称缓解 — 或把结算价格或赔率本身当作真理或合规判定。

<details>

- 一并阅读：凡被实质牵涉之处，适用[可审计性](core_05_band_oversight.md#auditability)、[可质疑性](core_05_band_accountability.md#contestability)、[真理（宪法约束）](core_05_band_oversight.md#truth-constitutional-constraint)、[实质性认定](core_05_band_oversight.md#materiality-determination)，以及第十三章与第十五章机制。

</details>

<br>

*用直白的话说：本簇回答哪份文本有约束力、冲突中哪一源胜出、所主张的义务是否真正能被核验与执行，以及 — 连同序言主责登记 — 谁主责哪一主题。*

**接纳范围。** 本簇适用于一项事项实质关涉下列各项之处：

- 哪份文本有约束力；
- 版本保管；
- 各源之间的至上性排序；
- 纳入范围；或
- 所主张的义务是否可执行地奠基于已采纳文本库。

若事项落在该清单之外，[文本库](core_05_band_integrative.md#corpus) 与 [权威栈与内部层级](core_05_band_integrative.md#authority-stack) 仍可单独用作支持定义。不得只因那些用语之一出现，就把整簇拉进来。

凡接纳范围成立之处，本簇就是那些问题必须被一并回答的地方。它覆盖：

- **哪些文本算作官方宪法** — 已采纳、有版本的文本库，不是草稿、笔记或非官方副本；
- **权威在该文本库内部如何排序** — 主题重叠时哪些章节与层控制，包括[权威栈与内部层级](core_05_band_integrative.md#authority-stack) 下的主责不挪位与至上性效果；
- **有效采纳之后哪一源胜出** — 有约束力的义务在实际被采纳的范围内优先；以及
- **所主张的义务在实践中能否被核验与执行** — 经由[可审计性](core_05_band_oversight.md#auditability) 与 [可质疑性](core_05_band_accountability.md#contestability)，不是只在纸上主张。

当那些问题中任何一项在场时，把簇成员一并阅读，而不是把其中一项当作单独足够。

**簇成员。** 本簇包括：

- [文本库](core_05_band_integrative.md#corpus)；以及
- [权威栈与内部层级](core_05_band_integrative.md#authority-stack)。

[宪法约束](core_05_band_integrative.md#constitutional-constraint) 作为与本簇一并阅读的支持定义住在本节；除非被独立要求，它不是额外的联合调用成员。哪一章主责哪一实质领域的正向主责登记，住在[序言 — 正向主责登记](core_00_preamble.md#4-principles-definitions-and-rights)（第 4–7 节）。主责不挪位与至上性效果陈述于[权威栈与内部层级](core_05_band_integrative.md#authority-stack) 之下。有约束力主张的实务可执行性，在[可审计性](core_05_band_oversight.md#auditability) 与 [可质疑性](core_05_band_accountability.md#contestability) 下路由。治理层反替换（宪法契约对受影响方的系统参与）住在[序言 §3.3](core_00_preamble.md#33-governance-layers) 与 [宪法契约层](core_05_band_integrative.md#constitutional-contract-layer) 之下。

**反绕过。** 接纳范围内的事项不得被分割成单独的：

- 贴标签；
- 过程制品；
- 版本展示；或
- 解释性注解

问题，以致：

- 把无约束力材料当作操作性文本库；或
- 在无有效采纳路径的情况下颠倒至上性排序。

见 **联合调用与满足**。

*测量（族路由）：* 在监督测量族与问责测量族下测量。具体测量见下方成员定义。

<details>

</details>

<br>

*用直白的话说：文本库是官方、有版本的有约束力宪法文本集合 — 不是草稿、笔记或非官方副本。*

- **它是什么**
  - **范围内：** 有约束力宪法源的权威整合集合：
    - 作为单一文书阅读的编号 `core_*` 感知者宪法文件；
    - 过渡期间任何有效的兼容性包装；以及
    - 已采纳实施文本。

    源经[文本库与权威栈簇](core_05_band_integrative.md#corpus-authority-stack-supremacy-and-enforceability-cluster) 下有效的采纳与版本控制被版本化并保管。
  - **范围外：**
    - 未被有效纳入为有约束力文本的解释性笔记、过程制品、草稿或导航指南；以及
    - 被当作操作性版本出示的非官方或无版本副本。
<a id="corpus-a"></a>
- **如何测量与评估**
  - **主要测量：** [监督测量族](core_05_apex_oversight_leg.md#oversight-measurement-family) — *感知者对获授权宪法文本的边界是否清楚？*

    **主要评估：** 问一问所主张的有约束力文本是否是真实、有版本的文本库 — 而不是被当作法来对待的非官方副本、草稿或过程笔记。对合规与采纳主张，在可适用的[文本库与权威栈簇](core_05_band_integrative.md#corpus-authority-stack-supremacy-and-enforceability-cluster) 下识别操作性文本库版本与保管链。然后：
    - 把已纳入的有约束力文本与解释性或过程制品区分开；以及
    - 适用第十三章至上性与第十四章采纳条件。
<a id="corpus-c"></a>
- **必须成立什么**
  - **主要失败：**
    - 把分歧的、不受控的或被误认的文本表述为文本库；或
    - 在无有效纳入的情况下，把无约束力过程制品塌进有约束力范围，违反统管的[文本库与权威栈簇](core_05_band_integrative.md#corpus-authority-stack-supremacy-and-enforceability-cluster)。

  - **范围内：** 成对规则：先决定哪一类源在说话、它是否有约束力，贯穿操作性[文本库](core_05_band_integrative.md#corpus) — 只有那时，若有约束力的宪法内部仍有真实冲突，才决定如何解决。源层包括：
    - **有约束力的宪法源** — [序言](core_00_preamble.md)、[第一章](core_01_a_values_principles.md) 与本宪法其他编号章节，一并作为单一文书阅读；
    - **有约束力的已纳入实施源** — 已采纳实施文本中指定的义务，在[第十五章](../../core_15_amendment_ratification.md#chapter-fifteen-amendment-ratification-and-procedural-validity) 与 [第十六章](../../core_16_incorporation.md#chapter-sixteen-incorporation-bridge) 下的有效采纳与纳入范围内；以及
    - **过程与地图支持源** — 架构地图、工作清单，以及回归或证据记录（包括 [doc_architecture.md](../../doc_architecture.md)），除非一份有效采纳文书明示把它们纳入为有约束力。

    **权威栈：** 统管宪法解释、采纳效果与层地位、贯穿宪法层、已纳入层与支持层的有序权威源框架。

    **内部层级：** 在[第一章 — §8 宪法解释](core_01_b_interaction_interpretation.md#8-constitutional-interpretation) 下的整合阅读穷尽之后，解决有约束力宪法源内部真正剩余不相容的兜底解释排序规则。在该源之内：
    - 第一章原则统管高层宪法方向；
    - 条款级义务与权利底线统管具体操作性要求；
    - 原则仅在真正剩余不相容时控制条款；以及
    - 条款控制被当作独立实质注解阅读的定义。

    第五章典范定义继续统管每一层所用用语的含义。

    **二者边界：**
    - 权威栈决定哪一层源在说话，以及该层是有约束力的、已纳入的，还是仅支持的；
    - 内部层级决定：在正确源层被识别之后，若该有约束力文本内部仍有真实冲突，有约束力的宪法意味着什么。

    <a id="owner-non-relocation"></a>
    <a id="constitutional-owner-layers"></a>
    <a id="constitutional-owner-layers-a"></a>
    <a id="constitutional-owner-layers-c"></a>
    - **主责登记与不挪位：** 哪一章主责哪一实质领域的正向登记是[序言 — 正向主责登记](core_00_preamble.md#4-principles-definitions-and-rights)（第 4–7 节），与章节开篇主责声明一并阅读。该登记与本条目如此配合：
      1. 在权威栈下识别源地位；
      2. 在序言登记（以及该章有约束力的开篇主责主张）下识别实质主责者；
      3. 仅在有约束力宪法源内部真正剩余不相容时适用内部层级。
    - **不挪位规则：** 在普通运行下，一层主责层中的文本不得从另一主责层输入义务，除非经由：
      - 指针；
      - 一并阅读路由；或
      - 明示交叉引用。

      指针交叉引用、一并阅读路由，以及「实施属于」或「不得收窄」一类整合句，是被允许的。向非主责层作**实质性重述**即不合规。凡效力或治理章节使用触发、移送或升级语言之处，该语言作为**仅路由启发式**运行，除非主责章节另行明示。
    <a id="supremacy-and-enforceability"></a>
    <a id="supremacy-and-enforceability-a"></a>
    <a id="supremacy-and-enforceability-c"></a>
    - **至上性：** 文本库有约束力的义务在其有效的源、采纳与治理层范围内优先。该至上性效果，是把本条目与操作性[文本库](core_05_band_integrative.md#corpus) 以及可适用的采纳或纳入文书一并适用的结果 — 包括[第十四章](../../core_14_expansion_supremacy.md#3-supremacy-relative-to-other-binding-norms) 相对其他规范的至上性，以及[第十四章 §5](../../core_14_expansion_supremacy.md#5-relation-to-applicable-external-law) 对可适用外部法的不取代。实施、支持文本、私人安排、紧急框架或运营实践，不得在其有效范围内收窄那些有约束力的义务。

    有约束力主张的实务可执行性 — 可观察、可质疑的合规，而不是纸面承诺 — 在[可审计性](core_05_band_oversight.md#auditability) 与 [可质疑性](core_05_band_accountability.md#contestability) 下评估。治理层反替换（宪法契约对受影响方的系统参与）住在[序言 §3.3](core_00_preamble.md#33-governance-layers) 与 [宪法契约层](core_05_band_integrative.md#constitutional-contract-layer) 之下。

    对采纳者，**第十四章**中的[采纳者的内部层级](../../core_14_expansion_supremacy.md#31-internal-hierarchy-for-adopters) 在有约束力的宪法与已采纳实施文本之间的界线上适用同一成对规则：
    - 本宪法及其整合定义控制文本如何被阅读、什么算合规；以及
    - 已采纳实施文本仅在实际被采纳的范围内适用，并且不能撤回[第十三章不倒退](../../core_13_non_regression.md) 或本条目所陈述的至上性效果。
  - **范围外：** 支持文件注解、地图、工作清单或采纳品牌本身 — 那些不是权威栈的层；未被当作重排源优先顺序或取代有约束力义务而提出的可选指引。
<a id="authority-stack-a"></a>
- **如何测量与评估**
  - **主要测量：** [监督测量族](core_05_apex_oversight_leg.md#oversight-measurement-family) — *感知者能否分清哪一层源在说话、它是否有约束力、哪一章主责该主题、有约束力的义务是否在范围内优先，以及有约束力的宪法内部真实冲突如何解决？* [问责测量族](core_05_apex_accountability_leg.md#accountability-measurement-family) — 主责边界与至上性效果主张的支持测量。

    **主要评估：**
    - 先在权威栈下识别操作性版本/保管链与源层。
    - 再在[序言 — 正向主责登记](core_00_preamble.md#4-principles-definitions-and-rights)（以及章节开篇主责主张）中识别主责家园；只从该主责家园适用实质 — 他处只用指针。
    - 然后在[第一章 — §8 宪法解释](core_01_b_interaction_interpretation.md#8-constitutional-interpretation) 下适用整合阅读。
    - 保全宪法作为整合整体的最充分保护效果，以及[第六章](../../core_06_rights_part_a.md#chapter-six-foundational-rights) 的不收缩默认。
    - 只把内部层级用作兜底剩余规则；不得用它替换普通整合阅读，或解决对典范用语含义的单纯分歧。
    - 凡争议是用语含义之处，第五章典范定义在每一层统管。
    - 对经 CS、CI、CF 与 CJS 路由的实施主题，在主责识别之后适用 **CJS-0.1**（主题路由器）。
    - 确认有约束力的义务在有效采纳与治理层范围内优先，并且实施、支持、私人或紧急框架并不收窄它们。
    - 对那些主张的实务可执行性，适用[可审计性](core_05_band_oversight.md#auditability) 与 [可质疑性](core_05_band_accountability.md#contestability)；对契约对受影响方的路由，适用[序言 §3.3](core_00_preamble.md#33-governance-layers)。
    - 拒绝下列解释：
      - 颠倒源优先顺序；
      - 遮蔽源地位；
      - 把未纳入的过程文本当作有约束力的宪法；或
      - 让已纳入层或支持层收窄感知者宪法的含义。
    - 对任何关于存在层碰撞、主责边界穿越或至上性效果被击败的主张，适用第四章的负担、可追溯性与核验要求。
<a id="authority-stack-c"></a>
- **必须成立什么**
  - **主要失败：** 下列各项即不合规：
    - 在无有效纳入的情况下，把地图、工作清单、笔记或其他支持文本当作有约束力的宪法 — 或以与宪法[文本库](core_05_band_integrative.md#corpus) 相矛盾的方式适用已纳入实施文本；
    - 用编辑偏好、支持文件注解或采纳品牌来重排源层、发明影子或双重主责家园，或在权威栈与内部层级之外解决剩余冲突；
    - 用志向性语言或本地实践，在有效源与治理层范围内取代文本库有约束力的义务；
    - 在另一主责层内部实质性重述一层主责层的义务，包括把读者指引散文抬升为操作性效力；
    - 把效力或治理章节中的触发、移送或升级语言，当作最终分类或制裁法，而主责层把该权威保留给第八至十章；
    - 用过程、治理或实施框架来收窄、重新定义或挪走[第六章](../../core_06_rights_part_a.md#chapter-six-foundational-rights) 权利底线，违反[第十三章](../../core_13_non_regression.md) 不倒退与第六章开篇契约；
    - 当[序言主责登记](core_00_preamble.md#4-principles-definitions-and-rights) 已经指定典范家园时，在非主责层发明平行分类或工作流；
    - 以颠倒既定源层级的方式主张至上性或合规，或让实施、支持文本、私人安排、紧急框架或运营实践在有效范围内取代文本库有约束力的义务；
    - 把内部层级当作捷径，去挑选更苛刻的读法、把[第六章](../../core_06_rights_part_a.md#chapter-six-foundational-rights) 权利底线保护收缩到[第一章](core_01_b_interaction_interpretation.md#8-constitutional-interpretation) 明示允许之外，或在普通阅读中用一层源替换另一层；
    - 把第五章定义当作压过原则或条款的竞争法体（[第一章 — §8 宪法解释](core_01_b_interaction_interpretation.md#8-constitutional-interpretation)）；或
    - 对采纳者，把已采纳实施文本当作在采纳范围内压过本宪法，或当作放松[第十三章](../../core_13_non_regression.md) 不倒退底线（**第十四章**中的[采纳者的内部层级](../../core_14_expansion_supremacy.md#31-internal-hierarchy-for-adopters)）。

<a id="constitutional-constraint"></a>

##### 宪法约束

<details>
<summary><strong><span style="color: #2563eb;">溯源</span></strong></summary>

- 上游：原则：[第一章 §3 不可妥协的原则约束：安全与真理](core_01_a_values_principles.md#3-non-negotiable-constraints-safety-and-truth)；[第一章 §6 过程冲突解决](core_01_b_interaction_interpretation.md#6-process-conflict-resolution)。
- 一并阅读：[安全（约束）](core_05_band_continuity.md#safety-constraint)、[真理（宪法约束）](core_05_band_oversight.md#truth-constitutional-constraint)、[权威栈与内部层级](core_05_band_integrative.md#authority-stack) 与 [伤害](core_05_band_accountability.md#harm)。

</details>

<br>

*用直白的话说：宪法约束是一项有约束力的限度，决定一项主张、行动或实践在本宪法下是否有效 — 不是可选建议。约束按排序种类而来：更高种类控制，更低种类不得收窄它们。*

- **它是什么**
  - **范围内：** 本宪法施加的有约束力限度、条件或纪律，决定一项宪法主张、系统行动、治理行为、限制、披露实践、评价、实施实践或源层主张是否有效。

    宪法约束被分类为下列**种类**，从最高控制力到最低排序。更高种类控制更低种类：更低种类不得在其有效范围内收窄、重新定义或取代更高种类。本条目分类并路由种类；主责层义务仍住在其典范家园。

    1. **不可妥协的原则约束** — [安全（约束）](core_05_band_continuity.md#safety-constraint) 与 [真理（宪法约束）](core_05_band_oversight.md#truth-constitutional-constraint) 作为第一章不可妥协的边界。
    2. **权利底线约束** — 第六章最低限度与不收缩规则，防止实施、过程、治理、紧急、过渡或私人安排框架收窄受保护权利。
    3. **限制与限度约束** — [必要性](core_05_band_accountability.md#necessity)、[相称性](core_05_band_accountability.md#proportionality)、限制最少且有效的选择、有时限、可审查性，以及统管影响权利之限制的负担最小化纪律。
    4. **认识与披露约束** — [真理（宪法约束）](core_05_band_oversight.md#truth-constitutional-constraint)、[认识完整性](core_05_band_oversight.md#epistemic-integrity)、披露限度、发表限度、受保护数据与内部状态限度，以及安全敏感披露平衡。
    5. **评价约束** — [评价完整性约束](core_05_band_oversight.md#evaluation-completeness-constraint)、[实质性完整性约束](core_05_band_oversight.md#materiality-integrity-constraint)、时间一致性、替代指标偏离失效，以及第四章负担、可追溯性与核验要求。
    6. **运营与实施约束** — 能力、可行性、安全、保密、时限、技术或资源限度，仅在其有效采纳与源层范围内被承认，并且仅在它们不收窄更高种类之处。

  - **依赖于：** [权威栈与内部层级](core_05_band_integrative.md#authority-stack) — 构成性框架。
    - 约束的优先顺序与效力在权威栈下决定，包括：
      - 反绕过；
      - 修正效力；
      - 纳入；
      - 保管；以及
      - 源地位纪律。
    - 被分类的义务仍由其典范主责家园在[序言 — 正向主责登记](core_00_preamble.md#4-principles-definitions-and-rights) 下主责。
    - 有约束力约束主张的实务可执行性，在[可审计性](core_05_band_oversight.md#auditability) 与 [可质疑性](core_05_band_accountability.md#contestability) 下路由。
  - **范围外：** 并不决定一项宪法主张、系统行动或治理行为效力的可选指引、志向性规范或政策偏好。
<a id="constitutional-constraint-a"></a>
- **如何测量与评估**
  - **主要测量：** [问责测量族](core_05_apex_accountability_leg.md#accountability-measurement-family) — 支持测量。

    **主要评估：** 从上到下走完 O 中的种类清单。对眼前事项：
    1. 识别每一项具实质适用的种类 — 不要停在第一次匹配。
    2. 从（种类清单中所链的）其典范主责家园适用每一可适用种类。
    3. 凡种类冲突或看似冲突之处，更高种类控制；更低种类必须被读作满足、而不是收窄更高种类。
    4. 拒绝不点名种类与主责家园的笼统「约束」主张。
<a id="constitutional-constraint-c"></a>
<a id="constitutional-constraint-violation"></a>
<a id="constitutional-constraint-violation-a"></a>
<a id="constitutional-constraint-violation-c"></a>
- **必须成立什么**
  - **主要失败：** 下列各项即不合规：
    - 笼统援引「约束」以遮蔽哪一种类适用、或哪一主责层供给它；
    - 用更低种类 — 包括运营、实施、源层、紧急、过渡、保密、安全或可行性约束 — 收窄更高种类，包括：
      - 安全；
      - 真理；
      - 第六章权利底线；
      - 修正效力；
      - 可质疑性；
      - 可审计性；或
      - 救济通路；
    - 把种类标签当作统管该决定的具体 O/M/A/C 条目、权利底线条款或主责层规则的替代；
    - 适用一种类同时把另一具实质适用的种类分割出去；
    - 通过系统行为或结果实质降级安全、真理或其他有约束力的宪法要求，包括下列[伤害](core_05_band_accountability.md#harm) 效果：
      - 直接的；
      - 间接的；
      - 延迟的；或
      - 汇总的。
    - 把仅纸面违规（或缓解之后本身并非约束降级的有界剩余风险）当作已经回答了那一实质问题。
