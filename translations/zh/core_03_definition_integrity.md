本节统管定义在实践中必须如何被解释与适用。

- 定义必须根据完整功能系统条件下的可观察系统行为与结果来解释与适用。
- 削弱定义的完整语义、评估与合规范围的解释、构造与系统行为 — 对应其本体（O）、评估（A）与合规（C）组件 — 被禁止；本章[**第 2 节**](#2-non-compliance-from-observable-system-behavior)规定来自可观察行为与规避的不合规。
- 功能等价优于命名、结构、分解、表征或所声称的意图；系统所产生的结果统管它如何被分类与评价。

本节不定评价标准、证据充分性或举证责任，那些专由**第二章，第 1 节**与**第四章，第 1 节和第 4 节**统管。

### 2. 来自可观察系统行为的不合规

<br>

*用直白的话说：当系统实际所做或所产出者会打破一项定义时，该系统即不合规 — 在完整功能系统条件下判断，而不是只在纸上。规避意味着在定义被实际适用时削弱它。那就是第二章 §2.2 下的不合规 — 不论意图、知悉或所声称的宗旨。*

本节定义系统何时基于可观察行为与结果而不合规，包括：

- 所声称的行为或范围与实际效果发生偏离之处
- 跨时间、尺度、系统互动与运行条件的规避，凡那些要紧之处

系统不合规，若那些可观察项在其本体（O）、评估（A）与合规（C）组件被完整适用时会违反一项定义，不论所声称的结构、解释或实施。

**如何评估。** 系统不合规，若：

- 所声称的主张与实际可见者冲突：
  - 所声称的系统行为、表征或审计制品与可观察结果冲突；在该情形下，可观察结果统管
  - 所声称的系统范围与实际功能效果冲突；在该情形下，定义必须基于实际系统行为与效果而适用
- 一项定义在完整功能系统条件下未被完整满足：
  - 语义、测量、评估与合规范围一并（O、M、A 与 C）
  - 包括跨时间、尺度、相连系统与运行条件，凡那些要紧之处
- 一项定义仅在纸面上被满足，而该完整范围未被满足：
  - 仅在形式、表征、结构、过程或有限条件下
  - 与一项定义的完整保护、评估或合规范围不一致的结果
  - 定义组件仅在受限、非代表性或经选择构造的条件下被满足
  - 保全形式合规同时降低真实世界结果的解释

下列类型分节罗列常见模式。它们不取代上文的评估规则。

<a id="21-common-evasion-patterns"></a>
#### 2.1 常见规避模式

*用直白的话说：这些是系统可以看起来合规、却并未真正满足定义的常见方式 — 被掉包的测量、虚假纸面材料、被切掉的范围，或把所有人推离合规的激励。本清单并非封闭。各类型可以同时发生。把定义含义收窄，见 [§2.2](#22-reductive-evasion)。*

下列形式的规避被禁止：

- **虚假测量与纸面材料** — 通过所测量、所报告或所记录者声称合规，而不是通过定义所要求的结果：
  - 换入偏离定义所关涉者的测量、指标或描述，同时仍声称通过
  - 为分数或测量而优化，却使定义所要求的真实世界结果变得更差
  - 出示实质性地不实陈述系统实际所做、或其是否合规的记录、制品或证据
  - 在名称、结构或过程上满足要求，却不产生定义所要求的真实世界效果（亦见 [§2.1.1](#211-formal-label-and-representation-gaming)）
- **范围与边界手法** — 安排什么被计入、以及何时计入，使困难部分从未被检验：
  - 收窄评估或适用，以漏掉要紧的系统要素、效果或条件
  - 把责任拆到组件、行动者或时间上，以致无人必须为整系统满足该定义
  - 仅在观察、审计或有限窗口下显得合规，而在更广运行中打破该定义
- **激励陷阱** — 建造会系统性把系统推离合规的奖赏、压力或动态：
  - 制造激励、动态或均衡按常理会削弱合规的条件


<a id="211-formal-label-and-representation-gaming"></a>
##### 2.1.1 形式标签与表征博弈

*用直白的话说：若真实决定、保护或义务在要紧之时从未真正发生，则标签、分类或橡皮图章式审查不算数。*

这是**虚假测量与纸面材料**的一种聚焦形式。系统不得仅凭标签、形式分类、名义程序或表征来满足宪法定义，当定义所要求的真实效果、运行节奏或功能结果缺失时。被禁止的模式包括但不限于：

- 仅在名义上存在的 human-in-the-loop（人在环内）或 human-on-the-loop（人在环上）批准 — 在系统实际运行的速度上没有真实决定权
- 橡皮图章式审查、虚假审议，或被用来顶替所要求的负担或裁决的纸面记录分类
- 形式上的更名、重组或实体重分类，卸下义务却未在实践中转移责任
- 图方便的分类选择，抹去定义所要求的区分

凡形式结构变更具有实质性之处，适用[第一章 §11.6 继受责任与形式结构不得逃脱](core_01_c_stewardship_capacity_principles.md#116-successor-responsibility-and-formal-structure-non-escape)。

<a id="22-reductive-evasion"></a>
#### 2.2 缩减性规避

缩减发生在适用一项定义所产生的结果不满足其本体（O）、评估（A）与合规（C）组件的完整表达之处。系统不合规，若其对一项定义的解释或适用缩减了该定义的语义范围、评估严格性或合规要求，产生比完整定义所要求者实质更弱的保护或结果。

下列形式的缩减被禁止：
- 语义缩减：把一项定义当作描述性的，同时去掉规范或评估效力
- 程序缩减：把过程的执行当作足够，不论真实世界结果
- 形式缩减：把文档、结构或表征当作足够，而无功能效果
- 范围缩减：排除具实质性相关的条件、系统要素或效果
- 评估缩减：通过选择性适用，在实践中削弱所要求的评价条件
- 结果缩减：用替代指标、部分或中间结果顶替所要求的真实世界结果

<a id="23-cross-component-scope-integrity-constraint"></a>
#### 2.3 跨组件范围完整性约束
全部定义组件（本体（O）、测量（M）、评估（A）与合规（C））必须被适用于同一功能系统范围、评价条件与时域框架。全部组件必须在一致的范围、条件与时域语境下被联合满足。

跨组件的错位既是规避也是不合规，包括：
- 把本体组件适用于比合规组件更广或不同的系统范围
- 把测量组件适用于与它们所支撑的本体、评估或合规组件不同的范围、条件或时间框
- 在受限或理想化条件下满足评估组件，同时主张在完整运行下合规
- 在不同时间框、实例或系统状态上展示组件满足

<a id="24-cross-system-interaction-integrity-constraint"></a>
#### 2.4 跨系统互动完整性约束
系统必须作为其所运行的更广功能系统的一部分而被评估。该项评估包括上游依赖、下游效果，以及凡具实质性相关之处的互动路径。凡此类互动实质影响该定义所统管的结果之处，定义必须跨互动系统被适用。

系统不合规，若：
- 其行为与其他系统结合，产生违反一项定义的结果
- 它把效果外溢到其他系统、群体或环境上以保全局部合规
- 系统边界被用来排除具实质性相关的互动效果

<a id="25-temporal-integrity-and-continuity-constraint"></a>
#### 2.5 时域完整性与连续性约束
全部组件必须在系统生命周期内、在完整功能系统条件下被持续满足。

合规必须随时间维持，包括系统更新、版本变更、再训练、重新配置与部署语境转变。

系统不合规，若：
- 合规仅在某一时点或有限观察下被展示
- 系统变更降低或使先前已满足的定义组件失效
- 合规在生命周期各阶段被拆碎，以致没有任何阶段在完整条件下满足全部组件

<a id="26-uncertainty-integrity-and-non-exploitation-constraint"></a>
#### 2.6 不确定性完整性与不利用约束
凡存在不确定性之处，定义必须以保全其完整语义、评估与合规范围的方式被适用。适用必须发生在与潜在伤害、依赖与风险相称的条件下。不得用不确定性来削弱、拖延或回避定义的适用。

系统不合规，若它：
- 援引不确定性以推迟或回避评估或合规判定
- 不对称地适用不确定性以偏袒合规主张
- 放大歧义以削弱所要求的严格性或结果
- 要求无法达到的确定性才承认不合规

凡不确定性使具实质性相关的定义组件无法被确定地展示合规之处，系统必须满足与潜在伤害相称的预防性负担。未能如此即构成本节下的不合规，并且未满足[第四章，第 5 节 — 合规证据标准](core_04_burden_traceability_verification.md#5-compliance-evidence-standard)下的举证责任。

本章下、或所调用的**第五章**定义下，具实质性的**不合规**认定可携带一份[不合规认定画像](../../core_05_band_accountability.md#non-compliance-finding-profile)。该画像仅为定向与路由元数据。它：

- 可以点名最能描述该项失败的[宪法四元](core_00_preamble.md#constitutional-tetrad)腿与[两项宪法宗旨](core_00_preamble.md#two-constitutional-aims)定向 — 例如监督、参与或问责与繁盛或延续交叉
- 不改变底层定义是否被满足
- 不创建第二套判定标签
- 不取代[第八章](../../core_09_standing_assessment.md#chapter-nine-compliance-violation-and-standing-model)的贡献或违规测量

轨迹效果取决于正在被评估的是谁，以及该系统是否已被认证。下列分节设定那些情形。

<a id="31-standing-effects-for-already-certified-systems"></a>
#### 3.1 已认证系统的轨迹效果

若一系统已在[系统对齐认证](../../core_08_a_system_alignment_certification_evaluation.md#chapter-eight-system-alignment-certification)下运行 — 包括承认、有条件承认，或尚未过期的再核验 — 对该系统功能范围上具实质性的经核实不合规**必须**进入[第八章](../../core_09_standing_assessment.md#chapter-nine-compliance-violation-and-standing-model)对**该系统**的轨迹测量。只有通过[经核实输入门](../../core_09_standing_assessment.md#verified-inputs-for-standing)的事实才可进入。在第八章与第九章下测量并适用轨迹。重开、撤回或其他认证后果仍属[第七章](../../core_08_b_system_alignment_certification_record_process.md#16-reopening-drift-and-non-evasion)。它们不取代该系统的轨迹记录。

<a id="32-standing-effects-at-first-certification"></a>
#### 3.2 首次认证时的轨迹效果

若该系统仍处于其**首次**[系统对齐认证](../../core_08_a_system_alignment_certification_evaluation.md#chapter-eight-system-alignment-certification)且尚未被承认 — 包括承认被推迟或被拒绝之处 — 经核实的不合规主要决定第七章下的**认证结果**。该结果可以是有条件承认、推迟承认、不承认，或一项可比结果。当事实支撑时，那些认证记录仍可在[第七章 §15](../../core_08_b_system_alignment_certification_record_process.md#15-relationship-to-standing)下提供经核实的轨迹输入。本章不要求已认证运行中系统必须接收的同一套轨迹记录。

<a id="33-standing-effects-for-sentients-and-institutions"></a>
#### 3.3 感知者与机构的轨迹效果

感知者的轨迹仅在显示通向该感知者的经核实链接时才受影响。与不合规系统有关联并不足够。该经核实链接必须指向：

- 因果角色
- 义务
- 权威
- 控制
- 可预见性
- 受益
- 隐瞒
- 可行的预防能力

机构的轨迹在该机构是被评估对象时受影响，或在它被核实为不合规模式的载体时受影响。机构记录与个体感知者记录保持分开可追溯。那些情形在[第八章](../../core_09_standing_assessment.md#chapter-nine-compliance-violation-and-standing-model)与[第九章](../../core_10_standing_integration.md#chapter-ten-standing-effects-and-integration)下适用。认定画像帮助路由与审计。它本身并不设定轨迹结果、槽位、锁定、门或救济。

<a id="34-operational-constraints"></a>
#### 3.4 操作性约束

不合规也可以针对联合实施文本库中的操作性约束而被认定。默认认定画像以及它们如何附着于那些认定，在那里处理 — 不在本章。见 [CJS-3.1 宪法指南针与聚类地图](../../corpus_joint_structure/cjs_03_cross_implementation_operational_terms.md#cjs-31-constitutional-compass-and-cluster-map)。
