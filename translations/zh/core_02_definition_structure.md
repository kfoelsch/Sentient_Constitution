*用直白的话说：本节是第二章的职责说明。它主责定义栈的第一层：每一项宪法定义由相互链接的部分建造 — 一项用语是什么（O）、必须如何测量与评估（与评价交织的测量登记，M/E），以及实践中必须成立什么（C） — 并且那些部分必须保持对齐。满足一项而绕开另一项，不算数。执行、治理与测量运营住在其后各章，并且必须遵从本章所确立者。*

每一项宪法定义必须由相互链接的部分构成，每一部分恰好一项工作：
- **本体（O）** — 该用语关于什么。
- **测量（M）** — 每一层级适用哪一项测量。测量路由指向评估；它不定通过/不通过的结果。
- **评估（A）** — 该用语必须如何被评估。在第五章叶定义上，**测量（M）**登记被织入**评估（A）**组件。见 [§1.3 评估组件](#13-assessment-components)。
- **合规（C）** — 实践中必须为真者。

那些部分必须在每一项定义内部保持一致。执行、治理、实施、测量运营、审计，以及超出定义范围的分类机制，属于其后各章；它们必须遵从此处确立的[宪法约束](../../core_05_band_integrative.md#constitutional-constraint)。

每一项定义必须就系统实际运行的整体而被满足 — 包括跨感知者、机器与地点分布的系统。O、M、A 与 C 各部分必须一并通过，在同一范围、同一检验条件下。靠切掉系统片段、收窄什么算数，或削弱另一部分来通过某一部分，不算数。

<a id="11-ontological-components-o-what-it-is"></a>
#### 1.1 本体组件（O）— 它是什么

*用直白的话说：O 部分回答一个简单问题 — **这项用语关于什么？** 它点名该物并画出其边界。它不说如何测量或判断该用语，也不说什么算通过或不通过；那些随后才来。*

本体部分（O）描述该用语关于什么。它不得说如何测量或评估该用语，也不得说什么算通过或不通过 — 那些住在测量（M）、评估（A）与合规（C）部分。它还必须匹配系统实际如何运作：一个名称、一个官方类别、一项管辖范围，或一项所声称的宗旨，在真实行为或真实效果另有说法时，并不能了结一项用语覆盖什么。

在一项定义上，O 部分写成一份带标签字段的短名单。每一字段回答一个直白问题：

- **范围内：** 该用语*确实*覆盖者。这列出系统的真实部分、它们如何一起工作、它们依赖什么，以及对本用语真正要紧的效果。
- **范围外：** 该用语*不*覆盖者。点名相邻概念、兄弟家园，或该事项之外的普通情形 — 不是空洞标签、纸面替代物或其他不合规框架。那些属于 C（**主要失败**）。
- **依赖于：** *（仅在适用时使用）* 任何本用语建立其上的*其他*、已定义之物 — 例如一项限度、一项最低底线，或它假定已经就位的目标。若该用语只有在那另一物存在时才说得通，则在此点名。

有些东西被有意**不**放进 O 部分：

- 该用语所*输入*者，或它所*归属*的更大组别 — 那属于该定义的交叉引用，不在此处；
- 该用语如何被测量或评估 — 那属于 M 与 A；
- 什么算满足或打破该用语 — 那属于 C，包括在无真实效果时声称满足的标签或纸面材料。

第五章叶定义必须用本节所述本体组件形态承载那些 O 要求。

#### 1.2 测量组件（M）— 必须如何测量

*用直白的话说：M 部分回答一个简单问题 — **为判断这项用语，我们应当看什么？** 它点名适用的测量。它不说该用语通过或不通过；那随后才来。*

测量部分（M）说明每一层级对一项用语适用哪一项测量。它把评估指向正确证据。它不得说什么算通过或不通过 — 那只属于合规部分（C）。

在第五章叶定义上，M 被织入评估部分（A），处于面向读者的标题 **如何测量与评估** 之下。每一层级先点名其测量，然后在紧接其下的一行给出对应评估。这些字段如下：

- **主要测量：** 首先要看的主要之物 — 评估者对此用语在此语境下应跟随的第一条证据线索。
- **次要测量：** *（在适用时使用）* 必须与主要测量一并纳入的额外测量 — 不是可选项的附加。它们加宽核验，使问题无法藏在狭窄的证据切片之后。
- **第三级测量：** *（在适用时使用）* 对测量本身的完整性核验 — 尤其在数字、标签、自我报告或形式类别可能顶替真实结果之处。

并非每个定义都需要全部三个层级。有些用语只声明一项主要测量；另一些在该用语需要更广或更深核验时，加入次要或第三级测量。

有些东西被有意**不**放进 M 部分：

- 什么算满足或打破该用语 — 那属于 C；
- 该用语关于什么 — 那属于 O；
- 单独的完整评估义务 — 那属于 A（尽管每一项测量都与紧接其下那一行的评估成对）。

第五章叶定义必须用本节所述测量组件形态承载那些 M 要求。

#### 1.3 评估组件（A）— 必须如何评估

*用直白的话说：A 部分回答一个简单问题 — **这项用语必须如何被判断？** 它说明评估者必须看什么、在何种条件下，以及如何处理不确定性。它不说该用语通过或不通过；那随后才来。*

评估部分（A）说明一项定义必须如何被评估。它不得说什么算通过或不通过 — 那只属于合规部分（C）。

在第五章各项用语定义上，测量（M）与评估（A）一并出现在题为 **如何测量与评估** 的一节中。

在该节之内，每一层级是一对：测量在先，对该测量的评估坐在紧接其下的一行。评估字段如下：

- **主要评估：** 如何判断主要测量 — 评估者必须首先评估什么，以及该项核验必须实际达到什么（实质，而不只是标签或纸面材料）。
- **次要评估：** *（在适用时使用）* 如何判断次要测量 — 当主要测量看起来没问题、但更广的证据仍然要紧时，必须纳入什么。
- **第三级评估：** *（在适用时使用）* 如何判断第三级测量 — 核验替代指标、度量或形式类别是否仍跟踪真实结果。

在所有层级上，A 部分必须：

- 说明必须评估什么；
- 说明评估必须在何种条件下发生；
- 说明在要紧之处如何处理不确定性。

有些东西被有意**不**放进 A 部分：

- 什么算满足或打破该用语 — 那属于 C；
- 该用语关于什么 — 那属于 O；
- 单独在每一层级适用哪一项测量 — 那属于 M（尽管每一项测量都与紧接其下那一行的评估成对）。

第五章叶定义必须用本节所述评估组件形态承载那些 A 要求。

当这些评估规则被付诸检验时，判断必须建立在足够的真实证据上 — 而不是单凭主张或纸面材料 — 并且凡该用语适用之处，必须适用同一套规则。

<a id="14-compliance-components-c-what-must-be-true-in-practice"></a>
#### 1.4 合规组件（C）— 实践中必须为真者

*用直白的话说：C 部分回答一个简单问题 — **实际上必须成立什么，以及这项用语何时已被打破？** 它陈述必须被满足的真实世界条件，以及算数的失败 — 基于行为与效果中可以看见的内容，而不是系统对自己的声称。*

合规部分（C）陈述一项用语要被满足、在真实世界中必须成立的条件。它必须从可观察的行为与效果出发工作 — 而不是从系统自己的声称、纸面材料或所声称的意图出发。

在第五章各项用语定义上，合规部分（C）出现在标题 **必须成立什么** 之下。这些字段如下：

- **主要失败：** 该用语在主要层级被打破之时 — 例如当主要测量是空洞的、不可追溯的，或与系统实际运作方式相矛盾。
- **次要失败：** *（在适用时使用）* 该用语在次要层级被打破之时 — 例如当主要核验看起来稳定，但更广的某物仍然击败该用语，如它依赖的系统中的破裂，或与之互动的相连系统中的破裂。
- **第三级失败：** *（在适用时使用）* 该用语在第三级被打破之时 — 例如当一项替代指标或度量被单独当作足够，或当已知偏离被忽视或未予纠正。

并非每个定义都列出全部三个失败层级。有些用语只声明一项主要失败；另一些在该用语需要按层级对齐的破裂条件时，加入次要或第三级失败。

在所有层级上，C 部分必须：

- 陈述可观察且可执行的结果；
- 陈述该定义何时被满足或被违反；
- 保持绑定于真实行为与效果，而不是单凭标签、形式类别或所声称的宗旨。

有些东西被有意**不**放进 C 部分：

- 该用语关于什么 — 那属于 O；
- 适用哪些测量，或评估必须如何运行 — 那属于 M 与 A。

第五章叶定义必须用本节所述合规组件形态承载那些 C 要求。

### 2. 定义完整性要求
<details>

<br>

*用直白的话说：把一项定义建造正确还不够 — 它在被适用时必须保持完整。定义不得被分段满足、被解释削弱，或通过范围切割来博弈 — 包括优化一项测量，同时它所代表的结果在恶化。凡语言允许不止一种读法之处，选择保全完整保护范围的那一种。*

<a id="21-core-integrity-conditions"></a>
#### 2.1 核心完整性条件
每一项定义在适用时必须保持整体成立。[§1 宗旨与角色](#1-purpose-and-role)所要求的相互链接部分必须：
- 彼此仍然一致
- 全部一并被满足；只满足其中一项或两项不够
- 在同一系统、同一条件下被满足 — 不得在狭窄切片上通过一部分，又在不同切片上通过另一部分

任何一部分失败，即定义未被满足。

<a id="22-non-compliance-by-structural-or-applied-weakening"></a>
#### 2.2 因结构或适用削弱而不合规
一项定义未被满足，若其构造、阅读或适用方式使一部分被满足，同时：
- 削弱、绕开或与另一部分冲突
- 产生在整系统运行时不会满足该定义完整含义、评估与真实世界要求的结果
- 允许只部分通过、只对选定情形通过，或只在某些条件下通过 — 那些通过在定义实际要求的条件下站不住

<a id="23-construction-constraints"></a>
#### 2.3 构造约束
定义必须写成：
- 所有部分 (O, M, E, C) 只能在反映系统真实行为及其真实产出的条件下一并被满足
- 任何一部分都不得靠概括化、拆分、收窄范围，或以漏掉真正要紧的系统要素、互动或效果的方式来描述，而被满足
- 任何测量都不得顶替它本应捕捉的结果；偏离其所代表真实世界结果的测量（见[替代指标偏离](../../core_05_band_oversight.md#proxy-divergence)）不能满足该定义，并且测量的选择不得收缩必须被评估者，或实践中必须成立者
- 任何未陈述的假设、隐藏依赖或被省略的条件，都不得改变或削弱必须被评估者，或实践中必须成立者

<a id="24-interpretation-rule-under-ambiguity"></a>
#### 2.4 歧义下的解释规则
当一项定义可以有不止一种合理读法时，使用保持其完整含义的读法。该读法统管该定义如何被适用。该读法还必须使评估保持严格，并且必须使真实世界要求保持完整。

不得用一项定义来判断或决定合规，若适用它会迫使定义内部出现矛盾、所陈述范围与实际必须覆盖者之间出现缺口，或一部分通过而另一项被要求的部分被绕开。

一项破裂的定义本身即不合规。即使系统看起来运行良好，即使尚未出任何问题，这一点仍然成立。

若一种合理读法会削弱保障、收窄必须核验者，或降低所要求的真实世界结果，而措辞与结构还允许另一种读法，则该较弱读法不被允许。

### 3. 跨定义栈的一致性
<details>
<summary><strong><span style="color: #2563eb;">溯源</span></strong></summary>

- 上游：原则：[§2 定义完整性要求](#2-definition-integrity-requirement)；[§1 宗旨与角色](#1-purpose-and-role)。
- 下游：[第三章，第 2 节 — 来自可观察系统行为的不合规](core_03_definition_integrity.md#2-non-compliance-from-observable-system-behavior)；[第四章，第 2 节 — 定义可追溯性要求](../../core_04_burden_traceability_verification.md#2-definition-traceability-requirement)；第四章第 **4.1**、**3**、**5** 与 **6** 节中，「合理可预见」出现且没有指向第五章的行内指针之处。
- 一并阅读：[第五章聚类定义（可预见性勤勉）](../../core_05_band_oversight.md#foreseeability-diligence) — 统管第二至四章中每一处「合理可预见」的规则；操作性含义在[合理可预见](../../core_05_band_oversight.md#reasonably-foreseeable)（第五章，第 3 节 — 依赖聚类（真理与认识完整性聚类；可预见性勤勉））。

</details>

<strong><span style="color: #2563eb;">定义：</span></strong> [可预见性](../../core_05_band_oversight.md#foreseeability-diligence) · [O](../../core_05_band_oversight.md#foreseeability-diligence) · [M](../../core_05_band_oversight.md#foreseeability-diligence-a) · [A](../../core_05_band_oversight.md#foreseeability-diligence-a) · [C](../../core_05_band_oversight.md#foreseeability-diligence-c)

*用直白的话说：一项定义不只是必须在纸上保持整体成立 — 它必须在真实世界中跨定义栈保持整体成立。其各部分必须在正常、降级与对抗性运行中以同一方式对齐，随时间、跨相连系统、在你能够合理预见的每一种情形中，以及在对其语词的每一种公正读法下。*

凡「合理可预见」出现在**第二至四章**任何一处，它的含义恰好是第五章第 3 节 — 依赖聚类（真理与认识完整性聚类；可预见性勤勉）中的可预见性定义所说者 — 不得更松。每一次使用都必须清楚指回那些定义。

一项定义的各部分必须在以下方面保持一致：
- 系统运行所处的全部条件范围 — 包括正常运行、降级运行、对抗性压力、随时间的变化，以及与其他系统的互动，凡那些要紧之处。
- 每一种合理可预见的条件，如第五章第 3 节 — 依赖聚类（真理与认识完整性聚类；可预见性勤勉）（可预见性）所述
- 该定义的措辞与结构所允许的每一种合理读法
