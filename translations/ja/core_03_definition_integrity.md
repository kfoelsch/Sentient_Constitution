本節は、定義が実務でどう解釈され適用されなければならないかを統治する。

- 定義は、完全な機能システム条件のもとでの観察可能なシステム振る舞いと成果に基づいて解釈され適用されなければならない。
- 定義の完全な意味、評価、遵守の範囲 — その存在論（O）、評価（A）、遵守（C）構成要素に対応する — を掘り崩す解釈、組み立て、システム振る舞いは禁止される；本章の[**第 2 節**](#2-non-compliance-from-observable-system-behavior)は、観察可能な振る舞いと回避からの不遵守を特定する。
- 機能的同等は、命名、構造、分解、表示、または述べられた意図に勝る；システムが産出する成果が、それがどう分類され評価されるかを統治する。

本節は評価標準、証拠の十分性、または証明の負担を定めない。それらは**第二章、第 1 節**および**第四章、第 1 節および第 4 節**が排他的に統治する。

### 2. 観察可能なシステム振る舞いからの不遵守

<br>

*平たい言葉で言えば：システムは、それが実際にすることまたは産出することが定義を破るときに不遵守である — 紙の上だけではなく、完全な機能条件のもとで判断される。回避とは、定義が実際に適用されるときにそれを弱めることである。それは第二章 §2.2 のもとでの不遵守である — 意図、認識、または主張された目的にかかわらず。*

本節は、観察可能な振る舞いと成果に基づいてシステムがいつ不遵守であるかを定める。次を含む：

- 述べられた振る舞いまたは範囲が実際の効果から乖離するところ
- 時間、尺度、システム相互作用、運用条件をまたいだ回避が、それらが大切なところ

システムは、それらの観察可能なものが、述べられた構造、解釈、または実施にかかわらず、その存在論（O）、評価（A）、遵守（C）構成要素の完全な適用のもとで定義を侵害するであろうところで不遵守である。

**どう評価するか。** システムは次のところで不遵守である：

- 述べられた主張が実際に見られるものと衝突する：
  - 述べられたシステム振る舞い、表示、または監査成果物が観察可能な成果と衝突する；その場合、観察可能な成果が統治する
  - 述べられたシステム範囲が実際の機能的効果と衝突する；その場合、定義は実際のシステム振る舞いと効果に基づいて適用されなければならない
- 定義が完全な機能システム条件のもとで完全には満たされない：
  - 意味、測定、評価、遵守の範囲をともに（O、M、A、および C）
  - それらが大切なところでは、時間、尺度、接続されたシステム、運用条件をまたいで含む
- 定義が紙の上だけで満たされ、その完全な範囲は満たされない：
  - 形式、表示、構造、過程、または限られた条件においてのみ
  - 定義の完全な保護、評価、または遵守の範囲と矛盾する成果
  - 制限された、代表的でない、または選択的に組み立てられた条件のもとでのみ満たされる定義構成要素
  - 形式的遵守を保ちつつ実世界の成果を劣化させる解釈

下記の類型分節はよくあるパターンをカタログする。それらは上記の評価規則を置き換えない。

<a id="21-common-evasion-patterns"></a>
#### 2.1 よくある回避パターン

*平たい言葉で言えば：これらは、システムが実際には定義を満たさずに遵守しているように見えるよくある仕方である — すり替えた測定、偽の書類仕事、切り出した範囲、または皆を遵守から遠ざける誘因。一覧は閉じられていない。類型は同時に起きうる。定義が意味するものを縮めることは [§2.2](#22-reductive-evasion) で覆う。*

次の形態の回避は禁止される：

- **偽の測定と書類仕事** — 定義が求める結果を通じてではなく、測定され、報告され、または記録されるものを通じて遵守を主張すること：
  - 定義が何についてのものかから乖離する測定、指標、または記述をすり替えつつ、なお合格を主張すること
  - 定義が求める実世界の結果を悪化させる仕方で、得点または測定を最適化すること
  - システムが実際にすること、またはそれが遵守するかを実質的に誤って述べる記録、成果物、または証拠を提示すること
  - 定義が求める実世界の効果を産出せずに、名称、構造、または過程において要件を満たすこと（[§2.1.1](#211-formal-label-and-representation-gaming) も見よ）
- **範囲と境界のトリック** — 何が数えられるか、およびいつかを組み立て、難しい部分が決して試験されないようにすること：
  - 評価または適用を狭め、大切なシステム要素、効果、または条件を外すこと
  - 構成要素、行為者、または時間にまたがって責任を分割し、誰もシステム全体について定義を満たさなくてよいようにすること
  - 観察、監査、または限られた窓のもとでのみ遵守して見え、より広い運用では定義を破ること
- **誘因の罠** — システムを体系的に遵守から遠ざける報酬、圧力、または動態を組み立てること：
  - 誘因、動態、または均衡が当然のこととして遵守を掘り崩す条件をつくること


<a id="211-formal-label-and-representation-gaming"></a>
##### 2.1.1 形式的ラベルと表示の弄り

*平たい言葉で言えば：ラベル、分類、またはゴム印の審査は、本当の決定、保護、または義務が大切なときに実際には起きないなら、数えない。*

これは**偽の測定と書類仕事**の焦点を絞った形態である。システムは、定義が求める本当の効果、運用テンポ、または機能的成果が欠けているときに、ラベル、形式的分類、名目上の手続、または表示だけを通じて憲法定義を満たしてはならない。禁止されるパターンは、限定なく、次を含む：

- human-in-the-loop（ループ内の人間）または human-on-the-loop（ループ上の人間）の承認が名目上だけ存在する — システムが実際に走る速さでの本当の決定権限なしに
- ゴム印の審査、見せかけの審議、または紙の記録上の分類を、求められる負担または判定の代わりに用いること
- 実務で責任を移さずに義務を落とす形式的な改名、再編、または実体の再分類
- 定義が求める区別を消す都合のよい分類法の選択

形式構造の変更が実質的であるところでは、[第一章 §11.6 承継者の責任と形式構造による逃避の禁止](core_01_c_stewardship_capacity_principles.md#116-successor-responsibility-and-formal-structure-non-escape)を適用せよ。

<a id="22-reductive-evasion"></a>
#### 2.2 縮小的回避

縮小は、定義の適用が、その存在論（O）、評価（A）、遵守（C）構成要素の完全な表現を満たさない成果を産出するところで起きる。システムは、定義の解釈または適用が、定義の意味範囲、評価の厳格さ、または遵守要件を縮小し、完全な定義が求めるものより実質的に弱い保護または成果を産出するところで不遵守である。

次の形態の縮小は禁止される：
- 意味の縮小：定義を記述的として扱い、規範的または評価の力を除くこと
- 手続の縮小：実世界の成果にかかわらず過程の実行を足りると扱うこと
- 形式の縮小：機能的効果なしに文書、構造、または表示を足りると扱うこと
- 範囲の縮小：実質的に関連する条件、システム要素、または効果を外すこと
- 評価の縮小：選択的適用を通じて実務で求められる評価条件を弱めること
- 成果の縮小：求められる実世界の成果の代わりに代替、部分的、または中間の成果を置くこと

<a id="23-cross-component-scope-integrity-constraint"></a>
#### 2.3 構成要素横断の範囲誠実性制約
すべての定義構成要素（存在論（O）、測定（M）、評価（A）、遵守（C））は、同じ機能システム範囲、評価条件、時間枠に適用されなければならない。すべての構成要素は、一貫した範囲、条件、時間的文脈のもとで共同に満たされなければならない。

構成要素間の不整合は回避であり不遵守でもある。次を含む：
- 存在論構成要素を、遵守構成要素より広いまたは異なるシステム範囲に適用すること
- 測定構成要素を、それが支える存在論、評価、または遵守構成要素とは異なる範囲、条件、または時間枠に適用すること
- 制約されたまたは理想化された条件のもとで評価構成要素を満たしつつ、完全な運用のもとでの遵守を主張すること
- 異なる時間枠、事例、またはシステム状態にまたがって構成要素の充足を示すこと

<a id="24-cross-system-interaction-integrity-constraint"></a>
#### 2.4 システム横断の相互作用誠実性制約
システムは、それが運用されるより広い機能システムの一部として評価されなければならない。その評価は、上流の依存、下流の効果、および実質的に関連するところでの相互作用の経路を含む。定義は、そのような相互作用が定義に統治される成果に実質的に影響するところでは、相互作用するシステムにまたがって適用されなければならない。

システムは次のところで不遵守である：
- その振る舞いが、他のシステムと組み合わさって、定義を侵害する成果を産出する
- 局所の遵守を保つために、効果を他のシステム、集団、または環境へ外部化する
- システム境界を用いて、実質的に関連する相互作用効果を外す

<a id="25-temporal-integrity-and-continuity-constraint"></a>
#### 2.5 時間的誠実性と連続性の制約
すべての構成要素は、システムライフサイクルを通じて、完全な機能システム条件のもとで継続して満たされなければならない。

遵守は時間を通じて維持されなければならない。システム更新、版の変更、再訓練、再構成、配備文脈の移行を含む。

システムは次のところで不遵守である：
- 遵守が一時点または限られた観察のもとでのみ示される
- システムの変更が、以前満たされていた定義構成要素を劣化させ、または無効にする
- 遵守がライフサイクル段階にまたがって断片化され、どの段階も完全な条件のもとですべての構成要素を満たさない

<a id="26-uncertainty-integrity-and-non-exploitation-constraint"></a>
#### 2.6 不確実性の誠実性と非搾取の制約
不確実性が存在するところでは、定義は、その完全な意味、評価、遵守の範囲を保全する仕方で適用されなければならない。適用は、起こりうる危害、依存、リスクに比例した条件のもとで起きなければならない。不確実性は、定義の適用を弱め、遅らせ、または避けるために用いられてはならない。

システムは次をするところで不遵守である：
- 不確実性を呼び出して評価または遵守判定を先送りし、または避ける
- 遵守主張を利するように不確実性を非対称に適用する
- 求められる厳格さまたは成果を弱めるために曖昧さを増幅する
- 不遵守を認めるために到達不能な確実性を求める

不確実性が、実質的に関連する定義構成要素についての遵守の確定的な立証を妨げるところでは、システムは起こりうる危害に比例した予防的負担を満たさなければならない。それをしないことは本節のもとでの不遵守であり、[第四章、第 5 節 — 遵守証拠の標準](core_04_burden_traceability_verification.md#5-compliance-evidence-standard)のもとでの証明の負担に失敗する。

### 3. 不遵守所見プロファイル

<br>

*平たい言葉で言えば：何かが定義に失敗するとき、所見プロファイルは、それがどんな種類の憲法上の問題かを言う任意のラベルである — 経路づけと監査のため。合格/不合格の結果は変えない。整合認証のもとですでに走っているシステムについては、検証済み不遵守は軌跡に入らなければならない；感知者と制度は、結びつきが検証されたときにだけタグ付けされる。最初の認証は特別な場合である（[§3.2](#32-standing-effects-at-first-certification)）。*

本章のもと、または呼び出された**第五章**の定義のもとでの実質的な**不遵守**所見は、[不遵守所見プロファイル](../../core_05_band_accountability.md#non-compliance-finding-profile)を帯びてよい。プロファイルは向き付けと経路づけのメタデータにすぎない。それは：

- 失敗をもっともよく記述する[憲法四元](core_00_preamble.md#constitutional-tetrad)の脚と[二つの憲法上の目的](core_00_preamble.md#two-constitutional-aims)の向き — たとえば監督、参加、または説明責任が繁栄または継続と交差したもの — を名指してよい
- 基礎となる定義が満たされるかを変えない
- 第二の判定ラベルをつくらない
- [第八章](../../core_09_standing_assessment.md#chapter-nine-compliance-violation-and-standing-model)の貢献または違反の測定を置き換えない

軌跡効果は、誰が評価されているか、およびシステムがすでに認証されているかに依る。下記の分節がそれらの場合を定める。

<a id="31-standing-effects-for-already-certified-systems"></a>
#### 3.1 すでに認証されたシステムについての軌跡効果

システムがすでに[システム整合認証](../../core_08_a_system_alignment_certification_evaluation.md#chapter-eight-system-alignment-certification)のもとで走っているなら — 承認、条件付き承認、または期限切れでない再検証を含む — そのシステムの機能範囲についての実質的な検証済み不遵守は、**そのシステム**についての[第八章](../../core_09_standing_assessment.md#chapter-nine-compliance-violation-and-standing-model)の軌跡測定に**入らなければならない**。[検証済み入力ゲート](../../core_09_standing_assessment.md#verified-inputs-for-standing)を通った事実だけが入ってよい。第八章と第九章のもとで軌跡を測定し適用せよ。再開、撤回、または他の認証の帰結は[第七章](../../core_08_b_system_alignment_certification_record_process.md#16-reopening-drift-and-non-evasion)のもとにとどまる。それらはそのシステムの軌跡記録を置き換えない。

<a id="32-standing-effects-at-first-certification"></a>
#### 3.2 最初の認証における軌跡効果

システムがなお**最初の**[システム整合認証](../../core_08_a_system_alignment_certification_evaluation.md#chapter-eight-system-alignment-certification)にあり、まだ承認されていないなら — 承認が延期され、または拒否されるところを含む — 検証済み不遵守は、第一次には第七章のもとでの**認証の帰結**を決める。その帰結は、条件付き承認、承認の延期、非承認、または比較可能な結果でありうる。それらの認証記録は、事実が支えるときに、なお[第七章 §15](../../core_08_b_system_alignment_certification_record_process.md#15-relationship-to-standing)のもとで検証済み軌跡入力を供給してよい。本章は、すでに認証されて走っているシステムが受けなければならないのと同じ軌跡記録を求めない。

<a id="33-standing-effects-for-sentients-and-institutions"></a>
#### 3.3 感知者と制度についての軌跡効果

感知者の軌跡は、その感知者への検証された結びつきが示されるときにだけ影響を受ける。不遵守のシステムと結びついているだけでは足りない。検証された結びつきは次へのものでなければならない：

- 因果的役割
- 義務
- 権威
- 制御
- 予見可能性
- 便益
- 隠蔽
- 実行可能な予防能力

制度の軌跡は、制度が評価されている対象であるとき、または不遵守パターンの担体として検証されるときに影響を受ける。制度の記録は、個々の感知者の記録から別個にたどれるままである。それらの場合は[第八章](../../core_09_standing_assessment.md#chapter-nine-compliance-violation-and-standing-model)および[第九章](../../core_10_standing_integration.md#chapter-ten-standing-effects-and-integration)のもとで適用せよ。所見プロファイルは経路づけと監査を助ける。それ自体は軌跡の帰結、スロット、ロック、ゲート、または救済を定めない。

<a id="34-operational-constraints"></a>
#### 3.4 運用上の制約

不遵守は、共同実施コーパスにおける運用上の制約に対しても見出されうる。既定の所見プロファイルと、それらがそれらの所見にどう付着するかは、そこで扱われる — 本章ではない。[CJS-3.1 憲法の羅針とクラスター地図](../../corpus_joint_structure/cjs_03_cross_implementation_operational_terms.md#cjs-31-constitutional-compass-and-cluster-map)を見よ。
